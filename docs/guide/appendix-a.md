# Appendix A — User-focused commands

These are commands a **human** runs interactively at a terminal. An agent reads this appendix only to point a user at the right command — never as part of its own working flow. This is a global appendix: user-only commands from any command group are collected here.

## Session navigation, observation, and history

Interactive commands on the `session` group:

- **`endless session goto <target>`** — switch tmux focus to a task's or session's pane, pushing the current pane onto a per-client back-stack. `<target>` is a task id (`E-NNNN`/`NNNN`) or a session id (`ES-NNNN`, a bare integer, or a Claude UUID prefix); a task id resolves to the most-recently-active live session working it. Prefer `ES-NNNN` — the form `task show` prints under `Created:`/`Touched by:` — since a bare integer matching both a session and a task is rejected as ambiguous. Requires tmux. `--resume` relaunches a target with no live pane in a NEW window (named `E-NNNN` for the task it holds) rather than erroring; on a target whose task is settled (`confirmed`/`assumed`/`completed`) it then requires **`--revisit`** (flip the task to `revisit` and continue work) or **`--no-revisit`** (read the session back, leave the status alone), because those mean opposite things and neither is a safe default. A target whose Claude transcript file is gone is refused **before** the window is created — the defect was a window that came up, died with the claude inside it, and told you nothing — and **`--new-transcript`** is the give-up route: a plain `claude` in the task's worktree, no `--resume`. The new window carries the standard three-pane layout `task spawn` builds.
- **`endless session resume <ref>`** — relaunch a lost session in the CURRENT pane: resolves `<ref>` to a Claude UUID, cd's to its task worktree, and execs `claude --resume`. Unlike `goto`, ended sessions count — recovering the sessions a tmux crash orphaned is what it is for. `<ref>` takes the same forms as `goto`, and `ES-NNNN` is session-**explicit**: it never falls back to task `E-NNNN`'s session. A session that never claimed a task gets a container task (`Auto-resumed task for session ES-NNNN`, claimed straight to `underway`) and its worktree created, so there is somewhere to resume into. `--review`/`--reopen` rebuild a worktree dropped after landing; `--dry-run` resolves and creates everything but declines the launch, printing the resolved target as JSON. Because the exec replaces the current pane, it refuses without **`--force`** when that pane's session is working a task, and points at `session goto <ref> --resume`, which opens a new window instead — unless the target IS that task, since re-entering the task the pane already holds replaces nothing. It also refuses a window holding more than one pane, because it lays the standard three-pane layout out around the pane it takes over. Like `goto --resume` it refuses a gone transcript before launching anything, with the same **`--new-transcript`** route on: the window choice and the give-up choice are independent, so the flag is on both verbs.
- **`endless session back`** — return to the previous pane, browser-style: pops the back-stack `goto` built, skipping panes that have since closed. With an empty stack, returns to the spawning session. Requires tmux.
- **`endless session monitor`** — the live dashboard: loops the `session status` view, redrawing every 2 seconds and repainting only on change. The top-like pane you keep open all day; Ctrl-C exits. Takes the same `--all`/`--tree`/`--show-hidden`/`--only-hidden` options as `session status`, footer included.
- **`endless session history [session]`** — show the conversation history for a session (current by default).
- **`endless session search <query>`** — search across all session messages.
- **`endless session hide <ids...>`** / **`endless session unhide <ids...>`** — hide sessions from (or restore them to) `session list`. With `--task <id>` (repeatable) they switch senses entirely and hide/restore individual TASK rows in one session's `session status` view — see **Quieting a noisy status view** in `endless guide sessions`.
- **`endless session task add <ids...>`** / **`endless session task remove <ids...>`** — add tasks to a session's list as decided work (`queued`), or drop the association entirely. Distinct from `session hide --task`, which suppresses a row while keeping the association — see **Correcting what your session's list holds** in `endless guide sessions`.

## Project-wide attention triage

Interactive commands on the `project` group. Where the `session` views above answer *"what is next for the task I am on"*, these answer the other question: *"what, across every session in this project, is claiming my attention"*.

- **`endless project status [name]`** — that question, as one frame. Ranks every claim in the project loudest first: sessions blocked waiting on you (⚠), then unverified work awaiting your verdict (☑), outcomes awaiting a read (☰), plans awaiting approval (⚑), tasks somebody claimed and walked away from (◷), then the sessions that are idle (‖) or working (⟳). A live session and the task it claimed render as **one** row, carrying the task's id and title alongside the session's id and how long it has been in that state. `--all` adds spawnable `ready` work — a claim on capacity rather than on attention. `--json` dumps the rows, uncapped, each carrying its action. Defaults to the project enclosing the working directory; name another to read it from anywhere.
- **`endless project monitor [name]`** — the same board, live: redrawn every 2 seconds, repainting only on change. Ctrl-C exits.
- **`endless project monitor --tmux`** — open the board in the home it is designed for: a tmux session named **`e-<project>-monitor`**, the board on top and a bare shell beneath it for running `endless` commands against what the board shows. Focus lands on the shell. Idempotent — running it again switches to the session that already exists. `--no-switch` creates it and leaves you where you are. The name leads with the project because a tmux status line truncates it: `e-endless-monitor` shows as `e-endless`, readable and distinct from a session you named yourself. Set `tmux.session_name` in `.endless/config.json` (or the global `~/.config/endless/config.json`) to change it: a Go text/template with a `project` placeholder, documented with worked examples in `internal/config/README.md`. Whatever you name it, Endless marks the sessions it creates and refuses to take over one it did not, so a name that collides with a session you already keep open is reported rather than hijacked.
- **`endless project info [name]`** — the project's registration card: metadata, pending notes, dependencies. (This is what `project status` used to be, before the board took the name.)

The board's cap is **per rank**, not per board, and `--limit` sets it. A single board-wide cap would spend every row on the unverified backlog and push the sessions off the bottom, which is the disappearance the board exists to prevent. Each truncated rank prints `… N more <rank> (--no-limit)`, and the frame sizes itself to the height it actually has — so the loudest rows are always the ones on screen.
