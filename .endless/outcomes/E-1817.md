## 2. Findings, with the evidence

### 2.1 `Install / refresh` is stale in a way that misdirects, not just bloats

CLAUDE.md line 19 says:

> Run `just install` from the **main checkout**, never from a worktree — `uv tool
> install -e .` from a worktree would point the global tool at the worktree's
> source, which gets removed when the worktree is dropped.

E-1036 made that false. `justfile:install` detects a worktree
(`git-dir != git-common-dir`) and performs a **worktree-scoped** install that
explicitly never runs `ln -sfn` or `uv tool install`; it runs `go-work-init`,
`build`, `dev-sandbox-init`, `claude-settings-init` and prints "global
/usr/local/bin untouched." It also warns if the global symlink already points
into a worktree.

So the prose is wrong twice over: the hazard it names is gated in code, and the
prohibition steers an agent in a worktree *away from* the one recipe that is the
supported way to wire that worktree. Worst category in the audit — an unenforced
rule that contradicts an enforced one.

### 2.2 `Worktree setup (Go builds)` is a prose copy of a script header

Lines 25–32 list a four-command manual block; lines 34–42 explain the hook that
makes it unnecessary. `.endless/hooks/post-worktree-create.sh`'s own header
already carries that explanation — the go.mod-replace-depth reason, the
copy-don't-build rationale, the E-1662/E-1281 fallback consequence, the E-986
non-fatal contract — in more detail than CLAUDE.md's paragraph. And the manual
block is exactly what worktree-scoped `just install` bundles (§2.1), so the
block reduces to one command.

### 2.3 `Worktree setup (Claude hook override)` names binaries that no longer exist

Lines 46 and 50 describe the override as pointing at `<worktree>/bin/endless-hook`
instead of `/usr/local/bin/endless-hook`. E-1367 consolidated every per-binary
entry point into `endless-go`:

- `ls bin/` → only `endless-go`.
- `ls /usr/local/bin/endless*` → only `endless-go`.
- `justfile:104` **actively `rm -f`s** `/usr/local/bin/endless-hook` on every
  global install.
- This worktree's live `.claude/settings.json` invokes
  `<worktree>/bin/endless-go hook claude`.

The rest of the section (recipe refuses from main, mirrors user settings,
preserves `enabledPlugins`, sets `skip-worktree`, idempotent) is an accurate
description of the recipe — which is exactly why it does not need to be here.
The refusal is enforced by the recipe itself, with an error message.

### 2.4 `Self-dev DB sandbox` ships a command that does not exist

Line 68: `endless-sandbox destroy e-NNN`. Same E-1367 consolidation — that binary
is gone and is deleted by `just install`. Correct form is `endless-go sandbox
destroy e-NNN` (confirmed against `endless-go --help`: `sandbox
run|enter|init|bind|list|prune|destroy`).

The rest splits cleanly: the *behavioral* half (writes route to a sandbox, `--db
main` reaches the real ledger, `--db sandbox` for the Python CLI from a bare
shell) is what a session acts on and stays; the *mechanism* half (which env var
is injected where, E-1368/E-1513 history, "there are no longer any wrapper
scripts") is implementation and goes.

### 2.5 `Corrections / memory OFF` is the right content at 2× the needed length

Correctly classified self_dev and genuinely enforced where it can be
(`autoMemoryEnabled: false` in tracked `.claude/settings.json`; `merge=union` in
`.gitattributes`). But:

- The whole "Concurrent appends merge themselves" passage (3 paragraphs) is a
  lossy restatement of the `.gitattributes` comment, which is longer, more
  precise, and sits on the line that does the work. One sentence + a pointer.
- "It lives in `.endless/`, not `.claude/`" is archaeology about a retired path.
  Nothing acts on it.
- "Do not claim a lesson is or is not already in the file based on a `tail`" is a
  corollary of write-only; it survives as a clause, not a bullet.

Per the plan's E-2007 caveat, the trim keeps the invariants that survive any
mechanism (memory off and why; unconditional recording; your own worktree; write-only;
name the full path) and lets the mechanism be the short, replaceable part. E-2007
will rewrite that part; it should not have to rewrite 71 lines to do it.

### 2.6 The two product-invariant sections are documented better in code

- **`Which agent harness is this?` (115 lines, 27% of the file).**
  `internal/agentenv/agentenv.go`'s package doc and constant comments carry the
  same reasoning (why `agentenv` not `agent`, why identity-with-a-flag not a
  boolean, why `Unknown` is unsupported). The E-1997 shell-init exemption is
  enforced by a test: `tests/test_agent_env.py:336` asserts
  `HARNESS_EXEMPT_SUBCOMMANDS <= SANDBOX_SAFE_SUBCOMMANDS`, and `:251` asserts
  the refusal banner names CLAUDE.md. Nothing in the section changes what a
  session in *this* repo does — this repo runs `claude_cli`, so every gate it
  describes is inert here.
- **`One project-path spelling` (E-2002).** The section's own text says "see
  either file for why," i.e. it is already a pointer with eight extra lines.
  `internal/monitor/project_path.go`'s doc comment gives the full rule, the
  tilde-tolerance carve-out, the non-strict-resolve reason, and the concrete bug
  it closes.

Deleting both is the clearest application of ED-1564's "product invariants belong
in code comments beside the code that enforces them."

### 2.7 The lifecycle section is a verbatim duplicate — and deleting it touches code

`tests/test_status_lifecycle_sync.py` pins the mermaid block byte-identical
across `README.md`, `CLAUDE.md`, `docs/guide/index.md`. CLAUDE.md's copy is
therefore *provably* redundant with the guide's, which is the canonical
agent-facing surface. Deleting it is not free — see §3.

### 2.8 Finding 1 from the prior analysis: the guide already has the section

The recorded finding said the commit-to-main policy "lives only in `endless guide
orchestration`." Confirmed present at `docs/guide/orchestration.md:212`
("Commit-to-main policy"), as a table of what commits where plus "if you see
uncommitted changes in main that aren't on the allowlist, that's a bug worth
filing."

What it does **not** say is the thing the observed failure needed: *a refused
land is a STOP, and being asked to fix the blocker is not authorization to commit
on main.* So the gap is real but narrower than recorded — it is a missing
sentence in an existing guide section, not a missing section. It is product-wide,
so under ED-1564 it does not belong in CLAUDE.md either way. See §4.

### 2.9 Finding 2 (LESSONS.md destination) — verified resolved, no action

worktree**" with no contradicting clause, and `.gitattributes` carries the

## 3. Companion changes the apply-task MUST make

`FAILED tests/test_status_lifecycle_sync.py::test_copy_is_byte_identical_to_the_canonical_file[CLAUDE.md]`

this branch.)

`tests/test_status_lifecycle_sync.py:20` hard-codes
`_COPIES = ("README.md", "CLAUDE.md", "docs/guide/index.md")` and asserts each
file exists *and* contains the canonical block. Removing the lifecycle section
from CLAUDE.md without touching that test is a red suite.

Required, in one commit with the rewrite:

1. `tests/test_status_lifecycle_sync.py:20` — drop `"CLAUDE.md"` from `_COPIES`,
   and update the module docstring (line 4) which names the three copies.
2. `docs/status-lifecycle.mmd` line 2 — drop CLAUDE.md from "Embedded
   (byte-identical) in README.md, CLAUDE.md, and docs/guide/index.md".
3. Because that header line is *inside* the byte-synced block, editing it forces
   a re-sync of the two remaining copies: `README.md` and `docs/guide/index.md`.
   Re-run `just test` to confirm the sync test passes on the new triple.

## 4. Adjacent defects found while auditing (reported, not fixed)

The plan bounds this task to "CLAUDE.md prose only," so none of these were
changed. Each is small; each is a doc pointer that outlived what it points at —
the same failure mode ED-1564 names, which is what makes them evidence rather
than a digression.

- **`docs/guide/reference.md:240`** lists `/usr/local/bin/endless-hook` as the
  "Claude Code hook binary (Go)." Same E-1367 staleness as §2.3, but in the
  *shipped* guide, so it misleads every user's agent, not just this repo's.
- **`docs/status-lifecycle.mmd` line 4** (and therefore its three embedded
  copies) cites `tests/tasks/e-1648-verify.sh` as the test asserting the copies
  match. E-1889 promoted that assertion to
  `tests/test_status_lifecycle_sync.py`. The stale pointer aims a reader at a
  retired per-task verify script — precisely what the guide's own "a verify suite
  is a land-time gate" rule says not to run. Fix it while doing §3.2.
- **`internal/sandboxcmd/seed_worktree.go:132`** says the git-dir vs
  git-common-dir discriminator is "documented in this project's CLAUDE.md."
  CLAUDE.md does not mention it (it never has, in the current file). A dangling
  pointer today; strictly worse after minimizing. Point it at
  `internal/monitor/db.go`, which the same comment already names.
- **E-1816's wording is in the guide too.** The clause it flags — "background
  sessions may pick up only `ready` work" — exists at both `CLAUDE.md:346` and
  `docs/guide/index.md:85`. Deleting CLAUDE.md's copy (§2.7) removes one
  instance and **does not close E-1816**; the reword has to land in
  `docs/guide/index.md`. Worth noting on E-1816 so it is not marked done by the
  apply-task.
- **Overlap worth knowing, not a defect.** `internal/hookcmd/claude.go:626`
  ships `guidePointer` ("New to this project? Run `endless guide`…") in the
  first-injection context for *every* project, explicitly because this repo's
  CLAUDE.md says so. CLAUDE.md's line 3 therefore has a partial duplicate. Kept
  anyway: the injection is one-shot and delivery-recorded, so it is not
  guaranteed to reach a later session, and the line costs one line.

## 5. The handoff call: **options are limited** — file a todo, skip the brainstorm

ED-1564 is doing the deciding, and it decides cleanly. Every section sorts into
"true only here" (keep, trimmed) or "true everywhere" (already documented in the
guide or in code, delete). There is one obvious minimized file and it is written.
No section required a judgment call where a reasonable person would land
elsewhere — the closest was the harness section, and "this repo always runs
`claude_cli`, so nothing it describes ever fires here" settles it.

**File a todo that applies the diff**, scoped as: `cp` the proposal over
CLAUDE.md, plus the three companion changes in §3, plus (cheaply, while in the
neighborhood) the four adjacent fixes in §4. Verified by `just test` green and
the sync test passing on the new two-copy triple.

**One item does NOT belong in that todo and does need a brainstorm** — §2.8, the
missing "a refused land is a STOP" rule. Its options genuinely diverge:

- a sentence in `docs/guide/orchestration.md`'s existing Commit-to-main section;
- a code gate (`worktree land`'s refusal path, or the hook, noticing a commit
  landing on main from a session holding a task);
- nothing — accept that an agent rationalizing its way past a refusal is not
  fixable with more prose.

This audit's own direction argues against the first, and the observed failure
(the session *disclosed* the commit, i.e. it knew and did it anyway) is real
evidence against prose working at all. That is a design question about
enforcement, not a CLAUDE.md question, and it should not gate the apply.

Per the plan, neither follow-up is filed while this task is open.
