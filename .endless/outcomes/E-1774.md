# E-1774 — Concern taxonomy → proposed `task report --xml` element set

Grounds E-1771's `--xml` payload in what agents **actually** report at handoff,
then partitions each concern into **computed** / **validated-value** /
**free-text escape hatch**, and names the ceremony categories the schema
deliberately leaves unrepresentable. Recommendation only; E-1771 finalizes.

## Method

- **Inventory:** 183 Claude Code transcripts across 141 endless project dirs
  (`~/.claude/projects/*endless*/…jsonl`; main checkout + one dir per `e-NNNN`
  worktree). Final handoff = last `type:"assistant"` message with a non-empty
  `text` block.
- **Sampled the 28 most recent** sessions' final handoff/report messages and
  classified the distinct concerns each raised. The taxonomy stabilized by
  ~sample 15; later samples only reconfirmed it.
- **Grounded the "computed" bucket in code, not guesswork:**
  - `monitor.WorktreeAnomalies` (`internal/monitor/worktree_anomalies.go:46`)
    computes exactly four kinds — `uncommitted`, `detached-head`,
    `branch-mismatch`, `prunable` — with `AutoManagedStatusGlobs` (`:37`)
    filtering endless's own churn. Explicitly **not** anomalies: commits ahead
    of main, git tags.
  - **No external-service state is computed anywhere** — both surfaces
    (`worktree check`, `session status`) inspect only local git/worktree. This
    is why concern F below cannot be "computed."
  - Handoff templates (`internal/templatecmd/templates/handoff/*.tmpl` +
    `_close.tmpl`) already enumerate reporting categories and already carry the
    anti-ceremony rules ("relay `worktree check`", "flag external state only if
    in play", "do NOT confirm the negative", "exactly one verify command").

## Proposed `--xml` schema

**Key partition:** the agent's `--xml` payload carries *only* validated-value
elements and the free-text escapes. Everything computable is filled by the
command (which calls handoff-status internally) and assembled into the
self-complete relay output — the agent never types it, so it can never dress it.

### 1. Computed — NOT in the agent payload (command fills; agent supplies nothing)

- **Git/worktree anomalies** (D, E, P) — via `WorktreeAnomalies`; empty ⇒ zero
  output. Erases "tree clean", commit-delta, and gitignored-artifact ceremony.
- **Verify command** (A) — formula from task id; emitted for testable-behavior
  task types only (the template already branches verify vs non-verify).
- **Return line** (B) — formula from spawner pane / bg-vs-fg mode.
- **Follow-ups spawned + next-actions** (H, I) — query tasks/decisions created
  this session or linked `cleans_up`/`relates_to`; render id + title + status +
  the natural next verb. Repeats (list).
- **Deliverable pointer** (G) — the outcome/analysis lives on the task; render
  `task show <id> --outcome`.
- **This-task status** (J) and **epic children** (K, raw status) — status field
  / tree query.

### 2. Validated-value elements — agent selects; `none` = silence; out-of-set rejected

- `<tests result="passed|failed|red-expected|not-run|none" count="N?"/>` (C).
  Repeats: no. Attribute: `count` optional. `red-expected` is the load-bearing
  token — spec-first RED (e-986, e-1368, e-1417) is *expected* failure; a
  validated qualifier stops it being dressed as success or as alarm.
- `<external kind="none|ci-running|server-running|process-running|external-write"/>`
  (F). Repeats: yes (list). `none` renders as silence, so "no CI, no external
  services" has **no prose form**; only a real value is expressible. Recommended
  home for F rather than omitting it entirely, because genuine external state is
  real (if rare) signal the templates already solicit.

### 3. Free-text escape hatch — the genuinely non-computable, per-entry checked

- `<note kind="anomaly|discovery">…</note>` (D-real, M). Repeats. Attribute:
  `kind`. The one hatch E-1771 guards with the scoped per-entry Haiku check
  ("real thing the reviewer couldn't compute, or the absence of a problem?").
  Reference specimens: "MEMORY files edited outside the branch won't land";
  "base is behind main"; "E-1648 landed mid-session"; the e-1625 rebase-conflict
  resolution narrative.
- `<question>…</question>` (L). Repeats. Genuine "I finished but need your call
  on X." *Not* ceremony, so it takes a **different** per-entry check ("a real
  decision you need, or restating settled state?"), not the anomaly check.
  → Flag for E-1771: reconcile with E-1773's mid-session `FULL STATUS` bypass.

### 4. Deliberately given NO element (unrepresentable — this is the point)

- Clean-state confirmations: "working tree clean", "no anomalies", "nothing
  touched" (D/P) — silence via the computed anomaly set.
- "State outside endless: none" (F absence) — only a real `<external>` value is
  expressible; the *absence* has no representation.
- Landed-vs-worktree delta / "you own the land" (E) — expected pre-land state.
- This-task status recap (J) and pure children-status echo (K) — computed /
  visible in the session monitor.
- "What changed" prose (O) and self-correction/retraction (N) — the file-list is
  computed; rationale belongs to the plan/commit/chat, not the report.
- The **envelope** ("Here's my handoff! 🎉", "Everything checks out. Done."): no
  free-text wrapper exists — the command assembles the message and the agent
  prints it verbatim, so the "inventory of the silence" meta-ceremony (E-1760
  Turn 3) is structurally impossible, not merely discouraged.

## Notable schema decisions (recommended; E-1771 finalizes)

- **`tests` is agent-supplied, not command-run.** The agent has just-run
  knowledge; re-running the suite at report time is redundant cost, and a
  constrained token can't be editorialized, so validation still holds. (Alt: the
  command runs the verify script — heavier; noted only.)
- **`external` gets a structured element, not the free-text hatch** — it recurs
  as a category, and structuring it lets `none` erase the ceremony while keeping
  real values expressible.
- **`question` is a first-class free-text element distinct from `note`** — a
  large fraction of real sessions end awaiting a decision; folding it into the
  anomaly hatch would misapply the anomaly check to it.

## Illustrative payload (the normal, clean path)

```xml
<report><tests result="passed" count="19"/></report>
```

Everything else — anomalies (none → nothing), verify command, return line,
follow-ups, status — is computed and rendered by the command. The common case
makes **zero** Haiku calls (no free-text present), so structure-and-check costs
nothing on the normal path. A payload only grows `<external>`, `<note>`, or
`<question>` when there is a genuinely non-computable thing to say.
