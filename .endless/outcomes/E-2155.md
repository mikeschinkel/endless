## CONDITIONAL — 194, and what each gets

- **139 the site or its source already answers** — ~91 relays (the class travels
  with the relayed message) and ~48 resolved from state the site holds.
- **12 the command can resolve, and should** — from the actor, the call path,
  process ancestry, or state in hand. Not "it depends" once you use what Endless
  already detects: e.g. the live-session ambiguity refusals can resolve the
  session from `CLAUDE_CODE_SESSION_ID` instead of asking.
- **29 render as `report_if`** — they turn on what the user asked the agent to
  do, which exists only in the conversation. The refusal names both branches and
  the consequence; the agent decides. **A binary REPORT/NO-REPORT helper is not
  enough**, which the plan did not anticipate.
- **14 stop being conditional** — they belong to user-only commands (E-2162).

## Enforcement design (detail in the doc)

- **The class is in the name of the call.** Python: `Refusal.no_report / report /
  report_if / fault / relay`, `warn.*`, `info`, extending E-2097's
  `agent_error`. Go: `NoReport / Report / ReportIf / Fault / Warn / Info /
  Passthrough / Block`.
- **Python check:** an AST test fails on any `ClickException`/`UsageError`/
  `BadParameter` construction or subclass, `err=True` echo, stderr write, or
  non-zero exit outside the helper. Click's own usage errors and uncaught
  tracebacks are each classified once, in the root `main`.
- **Go check:** a `go/parser` test fails on any `os.Stderr` reference outside the
  package. There are 308 today, in 45 files; only 3 stderr writers are passed in
  as parameters, and those become a type with no `Write`.
- **Rendering:** humans see today's text. An agent sees the directive inside
  E-2097's verdict line, repeated first and last. A REPORT shows the decision and
  never the bypass (`--force`). Byte-identical across languages, pinned by a golden
  file.
- **Triggers:** environment, `--agent`, `--agent-view`, and `--format agent`.
  Harness detection is not widened, so an agent under an unrecognised harness
  reads as a human. `agent_facing()` gains the flags in the root argv pre-scan;
  Python sets `ENDLESS_AUDIENCE=agent` so endless-go renders for the same
  audience.
- **No ratchet.** The TSV already classifies every site, so each side converts in
  one land.

## Not in the inventory, but not out of scope for enforcement

- **INFO (27)**: stderr that is not a refusal — progress lines, a hook script's
  streamed output, status notes on commands whose stdout is `eval`'d.
- **EXCLUDED (128)**: output nobody receives — 39 `log.Printf` lines in hookcmd
  (the standard logger goes to stderr and `hook.log`; Claude Code discards a
  successful hook's stderr), tmux status-line stderr, background-job logs,
  exceptions caught and handled internally.

Enforcement still has to see both. A build check cannot tell a refusal from a
progress line by looking at the write, so every stderr write has to declare
which it is — including "this is not a refusal".

## What did not fit the rule

1. **Faults and environment dominate REPORT (165 of 200).** They are REPORT
   because the agent cannot continue, but they name no decision. The `fault`
   factory gives them one standard directive instead of 110 invented decisions.
2. **Warnings the user should act on, but that block nothing, become inert.**
   The rule makes them NO-REPORT, and they are addressed to the human.
   *Settled 2026-09-18: these go to the errors channel — `faults.Record` on the
   Go side, a new `endless-go errors record` verb for Python — so the user sees
   them on the session-status badge and the agent spends nothing.* The set:
   output style installed but not active (`outputstyle.go`, fires on every
   `register`), invalid `worktree_ttl` re-warned on every claim and land
   (`event.go`), worktree dir not git-ignored (`bind.go`, and Python
   discards that stderr on exit 0), the unminimized-report notice
   (`report_cmd.py`), unsupported harness (`cli.py`), the sigil synonym
   question only the user can answer (`sigils.go`).
3. **REPORT messages hand the agent the bypass.** `--force` on every drop
   refusal, `git worktree remove` (`worktree_cmd.py`), `reset --hard main`
   (`claude.go`), `task update --status revisit` on a declined task
   (`session_cmd.py`), `--cascade` (`task_cmd.py`),
   `--no-session` (`event_bridge.py`), `--write` for raw SQL (`cli.py`).
   By the rule's letter a named command reads NO-REPORT; each is a user act.
   *Settled 2026-09-18: a REPORT renders the decision and not the bypass
   (`human_remedy` is human-only), and the commands that are the user's alone
   refuse an agent outright (E-2162) rather than offering it `--force`.*
4. **Remedies that do not exist in a foreign project.** `just install`
   (`session_states.py`, `statuses.py`, `cli.py`,
   `worktree_cmd.py`, the task-status/session-state relays), `just land`
   (`worktree_cmd.py`), the retired `endless-sandbox` binary (`bind.go`,
   `sandbox.go`), `docs/status-lifecycle.mmd`
   (`status_transition.go`), Endless's own task ids in the rebuild guard
   (`rebuild_guard.go`), `endless pivot`, which does not exist
   (`claude.go`).
5. **Gates whose remedy the agent cannot perform.** The cwd gate says `/cd`,
   which the model cannot run, so every mid-session claim ends at the user
   (`claude.go`). The revisit gate says ask via AskUserQuestion, a tool the
   same gate blocks (`claude.go`). The `ended`-state gate is REPORT with
   nothing to decide (`claude.go`).
6. **Classification is only as good as the error that reaches the site.** Faults
   are swallowed upstream and surface as not-found (NO-REPORT): `_live_sessions`
   returns `[]` on any endless-go failure (`session_cmd.py`); a worktree
   in-use probe's cause is dropped because Python reads stdout
   (`worktree.go`); a failed Go schema change shows only "exit status 1"
   (`schemachange/errors.go`). Some real failures reach nobody at all: spawn
   launch failures after spawn-window reported success (`spawn_launch.go`), async hook faults, a dropped `$FULL` sigil (`sigils.go`).
7. **Refusals after side effects.** Several refusals fire after a partial write:
   `task update` refusals after the plan and outcome files are written and
   committed, `spawn` refusals after the task is already `underway` with a
   worktree, and a decision file written before a git failure raises. The largest
   is in the event pipeline — see *Defects found* below.
8. **One message, two audiences.** `hook.go` (the halt notice goes to the
   agent on PreToolUse and to the human on UserPromptSubmit/SessionStart/Stop).
   `claude.go` is written to the agent but only the user can act on it.
9. **Non-zero exits for non-failures.** "Nothing to roll back" and "already the
   shipped default" exit 1 (`minimizer_cmd.py`); an unbounded
   "re-run" with no escalation while the Stop gate holds the turn
   (`report_cmd.py`).

## Detection gap in trigger 1

The plan says trigger 1 keys on `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID` and
`AI_AGENT`. It does not: `agent_env.present()` is `detect() != UNKNOWN`, and
`detect()` recognises only `CLAUDE_CODE_ENTRYPOINT=cli`, `claude-desktop`, or the
Desktop bundle id. An agent in the VS Code extension (`vscode`) or the SDK
(`sdk-py`) reads as a human and would never see a directive. Settled
2026-09-18: detection is NOT widened — that is the behaviour, not a gap to fix
here.

## Decisions (Mike, 2026-09-18 — settled)

1. `--format agent` fires the directive; harness detection is not widened.
2. Conditions the command cannot resolve render as `report_if`; conditions it
   can resolve are resolved in code.
3. An unclassified error — a Go error at a generic print site, an uncaught
   Python traceback — renders as a fault.
4. Warnings that ask the user to act but block nothing go to the errors channel
   (`faults.Record`, and a new `endless-go errors record` verb for Python), not
   the agent's reply.
5. User-only commands refuse an agent outright rather than carrying a directive:
   `worktree drop`, `event rebuild-db --confirm`, `db restore`,
   `project unregister --purge`, the `setup` commands that write shell rc files
   and global Claude settings, and the user-owned status transitions (E-2162).

## Defects found, and where each went

All re-verified against the code; several reproduced in a sandbox. Items 3-8 are
folded into E-2159: each sits on a site that task converts, and each makes a
class or a verdict dishonest until it is fixed.

1. **→ E-1935.** Refused events are written to the durable ledger (reproduced). `event
   emit` appends and git-commits the ledger line before the executor's guards
   run; a refused change rolls back the database and stays in the ledger, and
   replay applies `status` unguarded.
2. **→ E-1063.** `endless guide` fails on any non-editable install: the guide is resolved
   from the source tree and the wheel ships no `docs/`.
3. **`decision add` with a repeated `--decides` id** creates the decision, then
   fails, so a re-run duplicates it (reproduced).
4. **`decision supersede` says "already superseded"** while the decision is still
   accepted (reproduced).
5. **`task add` crashes with a traceback** when committing a new verb fails.
6. **Research justification dead end** on `task update --type research`
   (reproduced).
7. **The revisit gate blocks AskUserQuestion**, the tool its own message names.
8. **The commit-on-main guard is bypassed by rewording** (`git -C . commit`).
9. **Dropped** (self_dev only, low reach): the sandbox reap guard hard-codes `main`; seeding
   re-derives the main database path.
