## CONDITIONAL — three different kinds (approximate keyword split)

- **~91 relays** — the site prints another process's output. The class has to
  travel with it: Go renders its own directive and Python's relay adds none.
- **~49 state** — computable at the site (status and type, `ErrNoProject` vs a
  DB error, EPIPE). They become REPORT or NO-REPORT at runtime.
- **~54 intent** — depends on whether the user or the agent supplied the input or
  asked for the act (`--cascade`, an ambiguous project name, a decline reason).
  The command cannot know that, so **a binary REPORT/NO-REPORT helper is not
  enough**: these need a `report_if(condition)` directive that hands the
  condition to the agent. The plan did not anticipate this.

## Enforcement design (detail in the doc)

- **The class is in the name of the call.** Python: `Refusal.no_report / report /
  report_if / fault / relay`, `warn.*`, `info`, extending E-2097's
  `agent_error`. Go: `NoReport / Report / ReportIf / Fault / Warn / Info /
  Passthrough / Block`.
- **Python check:** an AST test fails on any `ClickException`/`UsageError`/
  `BadParameter` construction or subclass, `err=True` echo, stderr write, or
  non-zero exit outside the helper. Click's own usage errors and uncaught
  tracebacks are each classified once, in the root `main`.
- **Go check:** a `go/parser` test fails on any `os.Stderr` reference outside the
  package. There are 308 today, in 45 files; only 3 stderr writers are passed in
  as parameters, and those become a type with no `Write`.
- **Rendering:** humans see today's text. An agent sees the directive inside
  E-2097's verdict line, repeated first and last. A REPORT shows the decision and
  never the bypass (`--force`). Byte-identical across languages, pinned by a golden
  file.
- **Triggers:** environment, `--agent`, `--agent-view`. `agent_facing()` gains
  `--agent` in the root argv pre-scan; Python sets `ENDLESS_AUDIENCE=agent` so
  endless-go subprocesses render for the agent too.
- **No ratchet.** The TSV already classifies every site, so each side converts in
  one land.

## What did not fit the rule

1. Faults and environment are 165 of the 200 REPORTs, and name no decision.
2. **Warnings the user should act on but that block nothing become inert:**
   output style installed but inactive, invalid `worktree_ttl`, worktree dir not
   git-ignored, unminimized-report notice, unsupported harness, the sigil synonym
   question.
3. **REPORT messages hand the agent the bypass:** `--force` and
   `git worktree remove` on drop, `reset --hard main`, `--status revisit` on a
   declined task.
4. **Remedies that do not exist in a foreign project:** `just install`,
   `just land`, the retired `endless-sandbox` binary, `docs/status-lifecycle.mmd`,
   Endless's own task ids, `endless pivot`.
5. **Gates whose remedy the agent cannot perform:** the cwd gate needs `/cd`; the
   revisit gate blocks the AskUserQuestion it prescribes; the `ended`-state gate
   has nothing to decide.
6. **Classification is only as good as the error that reaches the site.**
   Swallowed faults surface as not-found, and some failures reach nobody. The
   worst ones are folded into E-2159/E-2160.
7. **Refusals after side effects**, the largest being the ledger (below).
8. **One message, two audiences:** the hook halt notice.
9. **Detection gap:** trigger 1 recognises only the Claude Code terminal and
   Desktop, not the `CLAUDECODE`/`AI_AGENT` rule the plan describes. An agent in
   the VS Code extension or the SDK reads as a human.

## Defects found, not fixed, not filed

All re-verified against the code; several reproduced in a sandbox. Each needs a
filing decision.

1. **Refused events are written to the durable ledger** (reproduced). `event
   emit` appends and git-commits the ledger line before the executor's guards
   run; a refused change rolls back the database and stays in the ledger, and
   replay applies `status` unguarded.
2. **`endless guide` fails on any non-editable install**: the guide is resolved
   from the source tree and the wheel ships no `docs/`.
3. **`decision add` with a repeated `--decides` id** creates the decision, then
   fails, so a re-run duplicates it (reproduced).
4. **`decision supersede` says "already superseded"** while the decision is still
   accepted (reproduced).
5. **`task add` crashes with a traceback** when committing a new verb fails.
6. **Research justification dead end** on `task update --type research`
   (reproduced).
7. **The revisit gate blocks AskUserQuestion**, the tool its own message names.
8. **The commit-on-main guard is bypassed by rewording** (`git -C . commit`).
9. **`self_dev` only:** the sandbox reap guard hard-codes `main`; seeding
   re-derives the main database path.
