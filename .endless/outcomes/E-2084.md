# What must land and what must move before the Go port starts

Measured 2026-08-28 against main and the 137 worktrees on disk. Nothing was
moved, landed, blocked or re-parented — every item below is a proposal.

## The headline: the worktree backlog is a measurement artifact

The premise of question 2 was that 84 unsettled worktrees stand between here
and the port, several carrying hundreds of unlanded commits. That is not what
is on disk.

- **Of 86 unsettled rows, 14 carry any commit that is not already on main.**
  The test is `git cherry main <branch>`, which matches by patch-id rather than
  SHA. `worktree land` rebases before fast-forwarding, so a landed commit
  arrives on main under a new SHA and the branch's original copy reads as
  "unlanded" forever.
- **The large counts collapse to nothing.** E-1934's 314 unlanded commits are
  2 patches; E-1844's 223 are 4; E-1785's 198 are 2; E-1853's 182 are 6;
  E-1537's 122 are 2. The count measures how far the branch has diverged in
  SHA space, not how much work it holds.
- **Of those 14, four hold only a stale README rewrite** (`98bb7b24`,
  `4e611073`, present on E-1537/E-1785/E-1844/E-1934). E-1832 is `confirmed`,
  `tests/tasks/e-1832-verify.sh` is on main, and main's README is a *later*
  rewrite with a different tagline. Landing those two commits would revert it.
- **10 branches hold work of their own**, and only 5 of those touch
  `src/endless/*.py`.

### 37 worktrees are dirty from one hand-applied patch that main has superseded

37 of the 86 rows report `modified` solely because of an uncommitted edit to
`internal/monitor/db.go` — byte-identical in all 37, self-labelled "E-1972
compat sweep (2026-08-26)". It teaches `ProjectIDForPath` to try both the
absolute and the home-relative spelling of a project path, working around
E-2011 for binaries that predate it.

**Main already solves this**, and better: `ProjectIDForPath` now queries
`homeRelative(check, home)` directly. The patch is dead weight in every
worktree that carries it.

32 of those 37 carry no unlanded source work, and 25 of them carry nothing
else at all — discarding the patch (`git checkout -- internal/monitor/db.go`)
moves those 25 from unsettled to settled outright, with nothing to review and
nothing to land. That single sweep is most of the difference between an 86-row
backlog and a 14-row one.

### Three worktrees have no task row

E-1279, E-1293 and E-1361 have no row in main's `tasks` table — not removed,
absent. Their unlanded content is `.endless/` metadata only. E-2010 (below) is
the fix for the hard-deletion that produced them. Not a port blocker; its own
small decision, as the plan said.

## Question 2 — proposed landing list and order

Every branch below is 11–2200 commits behind main and needs `git rebase main`
in place before it can land. That rebase also dissolves the E-1891 concern in
the plan: after it, each branch runs main's Python against main's schema, so
"can this worktree still run `endless`?" stops being a question. Two of them
(E-1360, E-1643) have no `bin/endless-go` at all and need `just build` first.

branch rebases over settled ground rather than under it. E-2010 last because
it touches the most Python and would otherwise force every branch above it to
resolve against its 19-file rewrite.

### No action — 40 branches whose only unlanded commits are `.endless/` metadata

Ledger entries and plan mirrors. `worktree land` on these replays bookkeeping
and nothing else. Combined with the 31 hotfix-only worktrees, this is the bulk
of the 84 and none of the risk.

## Question 1 — proposed `blocked_by` edges on E-1063

A keyword sweep over the 487 open tasks returns 124 candidates under a
Go-or-Python regex, 66 under a tight one. As the plan predicted, almost all
are incidental. The judgement below sorts them by what the port actually needs
and what it actually destroys.

### BLOCKER — `endless task block E-1063 --by <id>`

| Task | State | Why it must land first |
|------|-------|------------------------|
| **E-996** | unverified | `go.mod` replace paths do not resolve from inside `.endless/worktrees`; the workaround is a hand-made symlink. Every port worktree is a Go build. This is the foundation. |
| **E-2019** | unplanned | Adopt goose and convert `internal/schema/changes/` to versioned migrations. Schema management must not change *during* a port. |
| **E-2020** | unplanned | Connect-time version verification and `endless db upgrade`. Pairs with E-2019; together they settle how a binary and a database agree, which the ported CLI inherits. |
| **E-1921** | unplanned | Research: must a test run build first? The port's entire safety net is "the tests pass". If `just test` can silently exercise a stale `bin/endless-go`, that net does not hold. |
| **E-1429** | unverified | Mandatory `--db main\|worktree` inside self-dev worktrees. The port rewrites this routing; settle the contract before rewriting it, not after. |
| **E-1668** | ready | Refuse a foreign `endless-go` self-detecting a worktree sandbox. Same contract as E-1429, and the port makes the binary user-facing. |
| **E-1661** | ready | Hook exits 2 on integrity/DB failure so agents actually halt. Ported code needs its failures to reach the agent, or port bugs land silently. |

### CHILD — re-parent under E-1063

The tree is deliberately flat, so this is short.

- **E-1189** (unplanned) — port `claude-settings-init` from a Justfile Python
  heredoc to Go. Deletes Python and produces Go. It *is* the port, in
  miniature.

E-894 is already a child and stays one.

### E-1486 — the one edge I am not deciding for you

E-1486 ("Remove all Python SQLite access") is currently `relates_to` E-1063.
Its own description calls itself "the missing middle between E-894 and
E-1063", and it is already decomposed into six children (E-1487, E-1488,
E-1490, E-1492, E-1493, E-1494).

Two defensible readings, and the choice changes the shape of the port:

1. **`blocked_by`** — E-1063 waits for E-1486. Python loses SQLite first,
   then the CLI moves to Go. Incremental, each step verifiable, and it keeps
   E-1486's existing decomposition intact. My recommendation.
2. **Child** — E-1486 becomes part of E-1063 and the two happen as one move.
   Less total work (you rewrite each call site once, not twice), but no
   checkpoint in the middle and a much larger single landing.

Reading 1 costs more work; reading 2 costs more risk. This is your call, and
it is the single largest structural decision in the port.

**E-2082** (submitted, research) is downstream, not upstream: it re-derives
two sections of E-1732's routing map *after* the port. Propose
`endless task block E-2082 --by E-1063`, the reverse direction.

### SUBSUMED — these stop existing once Go owns the surface (flag, do not close)

Each is a task about Python's implementation, not about behavior a user wants.
The port deletes the code and the task with it.

| Task | What the port does to it |
|------|--------------------------|
| **E-954** | Migrate Python config readers to Go merge semantics — there are no Python config readers afterward. |
| **E-1076** | Python boundary guard in `db.py`. Its own description already says it "becomes vestigial once E-894 moves all SQL to Go". |
| **E-1010** | Test infra for `click.testing.CliRunner` tests that bypass the Go binary. No Click, no CliRunner. |
| **E-1043 / E-1044 / E-1078 / E-1081** | pytest isolation and sandbox-fixture work. The suite the port leaves behind is Go's. |
| **E-1515 / E-1516** | Both are the same Python import-cache bug: `worktree land` loads post-merge code against a pre-merge module in one process. Go has no import cache. The bug ceases to exist. |
| **E-1938** | BLOB decode at Python's read boundary. Go's read boundary replaces it. |
| **E-1079** | Startup orphan warning hooked into Python's `main` entry point. The entry point moves. |
| **E-1042** | Document `ENDLESS_AUTO_MIGRATE`, a gate in `src/endless/db.py`. E-2019/E-2020 supersede it independently. |
| **E-1493** | Delete `docs_cmd.py`. Pure deletion — either land it cheaply now or let the port drop it. Do not port it. |

### ORDER-SENSITIVE — not blockers, but land-in-Python-now or redo-in-Go-later

These edit files the port rewrites. Each is small, so doing one twice is
cheap; the risk is doing all of them twice.

- `task_cmd.py` — E-932, E-982, E-1082, E-1157, E-1254, E-1336, E-1400, E-1406, E-1961
- `cli.py` — E-1306, E-1326, E-1805, E-967
- `worktree_cmd.py` — E-1336, E-1364, E-1418
- `session_cmd.py` — E-1395
- Cross-cutting — E-1980 (~20 UTC call sites, fixed at the display boundary)

Proposal: block the port on none of them, but **freeze new Python work in
those files the day the port starts**, and re-file anything still open at that
point against the Go implementation rather than carrying a Python patch that
has nowhere to land.

### NEITHER — no action

The remaining ~100 of the 124-task pool mention Go or Python incidentally
(tmux plumbing, docs, decisions, triage, verify suites). Leave them where they
are.
