# Outcome

## Pre-work scoping decisions (E-1941 session, 2026-08-12)

Recorded before the design work begins, so the deciding session inherits them
rather than re-deriving them. Everything below was settled with Mike during
filing. The decision this task exists to make — how to split per-worktree
storage from DB routing — is NOT among them and remains open.

**E-1957 stays blocked on this task.** E-1957 needs somewhere to persist git
conflict evidence when a land fails. The alternative considered was to unblock it
by making the existing fault surface project-aware instead. Mike chose to keep
the block: the intent is one coherent storage story — per-worktree storage, once
every project has a sandbox — rather than two mechanisms. So this task's outcome
determines where E-1957 stores evidence.

**The missing `errors.project_id` is a separate defect, not an input to this
decision.** It was initially recorded here as an alternative that had been
"considered and rejected," which was wrong: it conflated *where land evidence
lives* with *the errors table being unable to say which project a fault came
from*. The second is a design oversight in its own right — `endless errors show`
cannot filter by project, the status badge cannot be project-scoped, and the
unique index on `(source, code, fingerprint)` can collide across unrelated
projects — none of which depends on where E-1957 stores anything. Split out as
**E-1960**. This task neither depends on it nor blocks it.

**Fault-surface retention is deliberately out of scope.** Neither the `errors`
table nor the JSONL detail log has any sweep; `appendDetail` appends without
rotation and only manual `endless errors clear` exists. Mike's call: leave it
until it is needed. Do not fold it in here.

## Correction worth keeping

The `self_dev` gate on sandbox provisioning was never an intended design
decision — Mike's stated intent was always that every project gets a sandbox,
because a sandbox is where a worktree keeps the configuration a task needs in
order to be verified. It was recorded in a prior session as though the
downstream-projects-get-no-sandbox behavior were deliberate. Only the
`endless.db` routing is genuinely Endless-specific.
