# Version-control all multiline content as committed mirror files — PLAN

## Context

Today only a task's plan (`tasks.text`) is mirrored to a version-controlled file
`.endless/plans/E-NNN.md` (materialized + committed by `worktree_cmd.py`:
`_materialize_plan_file` / `_commit_plan_file_in_worktree`, per the E-1445/E-1525
machinery, ridden to main by worktree-land). Every OTHER multiline document field —
`tasks.outcome`, `tasks.analysis`, decision bodies — lives
only in the DB. If the DB row is lost or an authoring scratch file is referenced
instead of embedded (the corruption class E-1744 addresses), that content has no
git-backed copy to recover from.

This is the **durability belt** (belt-and-suspenders with the `/tmp`→`.endless/tmp`
task): even when content did make it into the DB, it should also exist as a
committed file so a human reviewing the repo on GitHub sees it and it survives a
dropped worktree / lost DB row.

## Approach

Generalize the existing plan-mirror path so it materializes+commits **every**
mirrored multiline field, not just `text`. For now, one subdir per field kind off
`.endless/` (Mike's steer — consolidate the naming convention later):
- `tasks.text`     → `.endless/plans/E-NNN.md`      (existing)
- `tasks.outcome`  → `.endless/outcomes/E-NNN.md`   (new)
- `tasks.analysis` → `.endless/analyses/E-NNN.md`   (new — analysis IS a multiline
  document field, e.g. E-1596's 9k-char analysis)
- decision bodies  → `.endless/decisions/ED-NNN.md` (new)
- NOT `tasks.description`: a short single-line metadata field, not multiline
  document content — no file mirror. (`title` likewise excluded.)

### Mechanism (reuse, don't fork)
- Extract the plan-mirror materialize/commit into a small field-agnostic helper:
  given (task/decision id, subdir, content), write `<worktree>/.endless/<subdir>/
  <ID>.md` and stage+commit it. `_materialize_plan_file` becomes one caller.
- Call it from the same CLI write paths that already set these fields
  (`update_plan`, `add_item`, `task complete/assume/replace`, `decision add`) —
  wherever the field's content is written to the DB, also mirror it, exactly as
  `text` is mirrored now.
- Only mirrors when a worktree exists (same as today: no worktree → DB-only, the
  file is born when the worktree is created at claim/spawn). Extend
  `create_task_worktree`'s birth-time materialization to seed ALL field mirrors,
  not just the plan.
- `.gitignore`: none needed — these dirs are tracked content (like `.endless/plans`).
