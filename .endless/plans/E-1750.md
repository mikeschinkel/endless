## Goal

Make the session-status list legend **dynamic**: include only the glyphs for actions actually present in the current view, rebuilt on each frame. Today the legend is a fixed single-line `const` listing every possible glyph, and it is space-constrained — new entries (notably `⁇ other`) were left out because the full set won't fit one line. Building it from only the present actions keeps it within one line in >99% of cases and lets otherwise-omitted glyphs appear in the legend exactly when they're on screen.

## Current state (all in `internal/sessionstatuscmd/session_status.go`)

- `const legend` (the fixed string) — the thing to replace.
- `action` enum + `func (action) icon()` — maps each action to its glyph; `actOther` returns `⁇` and is intentionally undocumented — today it is a catch-all for BOTH landed tasks (E-1693) and any unrecognized status. This task splits those apart (see Change).
- `classify(row)` — maps each row to its action.
- `renderTo` — prints the legend line, then the rows. Already emits the legend on every frame.
- `monitorLoop` — re-renders the whole frame each tick and repaints on change, so the legend already redraws per refresh; nothing blocks making it dynamic.

## Change

- Give each `action` a legend **label** (a table of action → {icon, label}), and derive the legend from that table instead of the hardcoded string.
- In `renderTo` (or a small helper), collect the distinct glyphs present in `rows` (reuse `classify` for actions; inspect each row for the decorations below), then build the legend from only those glyphs, in a stable order (enum order for actions, then decorations).
- **Drop the `|` group separator.** The legend is a single flat list of every glyph actually used, joined by the same two-space separator — no grouping divider.
- **Split the `⁇` catch-all into two actions** (now that the legend has room):
  - New `actLanded` — glyph **`⏚`** (electrical-ground = "landed/grounded"; decided with Mike 2026-07-09), label **`landed`**. In `classify`, change the pre-switch `if r.Landed { return actOther }` to `return actLanded`.
  - Residual `actOther` → rename to **`actUnknown`**, keep glyph `⁇`, label **`unknown`**. It now means *only* "a status the classifier doesn't recognize" — a should-never-happen safety net (every real status is already handled), so if `⁇` ever appears in the legend it flags an unhandled status slipping through. `⁇` finally matches its label.
  - Both get legend entries via the label table and appear only when a row of that kind is present.
  - Verify the `⏚` glyph is single-width with go-runewidth (as the existing `⁇` comment does) so table alignment holds.
- Include the per-row **decoration** glyphs in the same dynamic list, each shown only when a row bearing it is present:
  - `⊗ blocked` / `⏸ blocks` — the block markers (see `blockField`/the block-marker source).
  - `◆ dirty` — the `dirtyMark` glyph (worktree diverges from main / unlanded work, E-1701). **This reverses the earlier "◆ stays out of the legend" call (Mike, 2026-07-01): Mike now wants `◆` documented as `dirty`, dynamically like the rest.**
- Preserve the single-line intent. In the rare case the present set still exceeds width, prefer graceful handling (wrap or truncate) over padding with absent glyphs.

## Invariant: `session status` and `session monitor` render identically

`endless session status` (one-shot) and `endless session monitor` (redraw every 2s, `top`-style) must produce **the same output** — `monitor` is only `status` on a timer. They already share the single-frame renderer (`renderSnapshot`/`renderTo`); put the dynamic-legend logic there so both paths stay byte-identical by construction. The verify script must assert this parity (a single `status` frame equals one `monitor` frame for the same rows).
