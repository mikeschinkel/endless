# E-1202 — Block direct Write/Edit of plan files — PLAN

## Mechanism
A new preToolUse gate in `internal/hookcmd/claude.go` refuses any
Write/Edit/NotebookEdit whose target is a task plan file `.endless/plans/E-NNN.md`,
redirecting to `endless task update --text`. The CLI's own materialization
(`_materialize_plan_file` / `_commit_plan_file`, worktree_cmd.py) is untouched — it
is not a Claude tool call, so the hook never sees it; the land-produces-plan-markdown
flow is intact.

## Path pattern (resolved)
`planFileRe = regexp.MustCompile(`(^|/)\.endless/plans/E-\d+\.md$`)`
- Matches absolute (`…/.endless/plans/E-1202.md`) and repo-relative paths.
- Anchored `$`; requires `E-<digits>.md` immediately after `plans/`, so it EXCLUDES
  any subdirectory (e.g. a future `.endless/plans/snapshots/…`) and any non-plan file
  in the dir. Current layout is flat `E-NNN.md`; no snapshots subdir exists — verified.
- Does NOT touch Claude's plan-mode `plan.md` (different path + flow).

## Scope (resolved)
Fires for BOTH main and worktree targets. The gate matches ONLY the canonical mirror
path `.endless/plans/E-NNN.md` — drafting plan content to a temp path (`/tmp/...`) or a
gitignored local dir is fine and IS the workflow (author there, then
`task update --text`). Only `task update --text` writes the canonical mirror.
Independent of tracking_mode (like the worktree and commit-on-main gates).

## Changes
1. Add package var `planFileRe` and `blockPlanFileWriteIfApplicable(payload)` —
   model on `blockCommitOnMainIfApplicable`: `extractFilePath` -> regex test ->
   `blockToolUse(msg)`. Reuses existing `writeTools` / `extractFilePath`.
2. Call it in `handlePreToolUse`, in the write-tool section: AFTER the
   `if !writeTools[payload.ToolName] { return nil }` early-return and BEFORE the
   `enforceWorktreeGate` call, so a plan-file write in main gets the plan-specific
   message rather than the generic worktree refusal.
3. Block message (NO internal task IDs, per the user-facing-string rule):
   "BLOCKED: refusing a direct Write/Edit of a task plan file
   (.endless/plans/E-NNN.md). Plan content lives in tasks.text (the source of truth);
   the file is a mirror endless writes and commits for you so humans can see plans when
   reviewing the repo on GitHub or other Git hosts. Editing it directly leaves the DB
   stale, and if the worktree is later dropped the edit is silently lost.
   Author the plan at a temp path, then run:
     endless task update <id> --text <path>
   Never hand-edit or git-commit the plan file yourself."
