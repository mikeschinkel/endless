# E-1607 — Guide "Verification" section + wire the one-command handoff contract into spawn templates

## Context

The verify-suite convention (the E-1596 tree) has no guide section, and the six
spawn handoff templates state "how to test" as ad-hoc narrative that invites a
multi-command checklist. Document the settled convention and encode the
one-command handoff contract so future verify-handoffs are lean and reliably
produce a suite. Dogfooding target: the user runs one verification command; if it
passes, the task is done.

## Deliverables

### 1. New guide section: docs/guide/verification.md

`endless guide <slug>` is filesystem-based (the `guide` command in src/endless/cli.py
lists every docs/guide/*.md stem except `index`), so adding this file auto-registers
`endless guide verification` with no code change. Model tone and depth on an existing
topic page such as docs/guide/decisions.md. It must NOT cite internal E-NNN task ids
(shipped doc — inline the information instead). Content:

- The per-task verify-suite convention: one verification suite per task. Today it
  is realized as `tests/tasks/e-NNNN-verify.sh` — a self-contained bash script
  that builds an isolated env, prints pass/fail per check, ends in ALL PASSED, and
  exits 0 clean or 1 on any failure (point readers at an existing example script as
  the shape to copy).
- The settled `verify.toml` manifest as the emerging form the (in-progress) runner
  will execute — read the real field names from the internal/verify package:
  top-level `schema`, `task`, `setup`, `teardown`, `tiers`, `seed`, `needs`; a
  `[[check]]` list whose entries carry `runner` (first-class `gotest`/`pytest` or a
  raw runner), `tests`, `paths`, `command`, `format`; and the project-level
  `.endless/verify.toml` layer (project `setup`/`teardown`/`seed`/`needs` compose
  beneath the per-task manifest). Discovery: per-task `.endless/tasks/<id>/verify.toml`
  plus the project-root `.endless/verify.toml`.
- The one-command handoff contract (the load-bearing policy): at verify-handoff the
  session (a) runs project-wide regression itself (tests, lint, build) and REPORTS
  the outcome in prose, never as commands for the user to run; (b) hands the user
  exactly ONE verification command; (c) folds the task's own unit tests INTO the
  per-task suite as a fail-fast check; (d) never enumerates a manual checklist.
- A clearly-marked "Forthcoming" note: the `endless verify` / `just verify` runner,
  the runnability modes, and the tier ladder are in progress; until the runner ships,
  the convention is realized via the per-task script plus the project's own test
  command.
