# FULL STATUS bypass keyword + mid-session reporting guidance

## Mechanism (decided)
Both pieces live in the **handoff templates** — the same surface E-1759 rewrote,
NOT the `task report` output template. Specifically the shared partial
`internal/templatecmd/templates/handoff/_close.tmpl` (`{{define "handoff_close"}}`),
which all six per-type handoff templates pull in via `{{template "handoff_close" .}}`.

Two additions to the reporting discipline already in that partial:
1. **Route reporting through `endless task report`** — state, as the default,
   that end-of-session and status reporting are produced by feeding the
   structured payload to `endless task report <id> --xml` and relaying its
   output verbatim, not composed as freeform prose. (This is the line that
   references E-1771's command — see Blocked-by.)
2. **`FULL STATUS` bypass keyword** — when the user types `FULL STATUS`, the
   agent answers UNCONSTRAINED for that one response (per-response, not a sticky
   mode). This is the explicit "elaborate when I ASK" lever.

## Scope
**Spawned sessions only** for now — the handoff templates reach only sessions
started via `endless task spawn`. Extending the discipline (and `FULL STATUS`)
to non-spawned sessions would mean the all-sessions SessionStart injection
(`FormatTasks` in `internal/monitor/task.go`), which currently carries only task
facts. Deferred: revisit only if ceremony proves a problem in non-spawned
sessions.

## Tunability (free)
Handoff templates honor `.local.tmpl` → `.tmpl` → embedded precedence, so
`FULL STATUS` and the reporting posture become per-project overridable without
touching product source — the "user lever" principle from ED-1531 at no extra
cost.

## Blocked-by E-1771
The routing default (#1) references `endless task report`, which E-1771 builds.
Landing that line before the command exists would point live spawn prompts at a
missing command. The `FULL STATUS` half (#2) is independent, but the task is
gated as a unit so the template lands coherent once the command exists.

## Verification
Per-task script `tests/tasks/e-1773-verify.sh` (model: existing
`tests/tasks/e-1577-*`). The deterministic surface is the *rendered* handoff
output, so the script renders the handoff templates and asserts content:

1. For each handoff type (`endless-go template render handoff/<type>.md` with
   sample render data — foreground and `.bg` variants), assert the output now
   contains:
   - the `FULL STATUS` bypass instruction, and
   - the "route reporting through `endless task report`" default.
2. Assert the pre-existing discipline is intact — the `endless worktree check`
   line, the "do not confirm the negative" clause, and the return line
   (foreground) / background stop instruction (`.bg`) — so the additions did not
   displace what E-1759 established.

The behavioral half (an agent actually answering unconstrained on `FULL STATUS`)
is guidance, not script-testable; it is exercised in use, not asserted here.
