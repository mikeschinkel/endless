# Spec

## 1. Style content (scope "b")

Start at "b" and optimize from there, per user direction. The style carries:

1. **Response shape** — no preamble or postamble; do not re-narrate what a tool just
   printed; do not summarize a file the user is about to read.
2. **The discharged-fact test** — what agent output may leave unsaid.
3. **The veracity requirement** — any surfaced fact must be verified against live
   state at the moment of surfacing, never recalled.

(2) and (3) are the parts of E-1876 that went obsolete undelivered: E-1911 replaced
E-1876 without shipping them. A style is a better host for them than a hook, because
they describe how to write, not a condition to detect.

Consider folding in E-1893 (replies restate the task IDs they are about) — it is
style-shaped and currently unplanned.

Author **one** style, not several: only one can be active at a time, and multiple
bespoke styles fragment the contract.

Set `keep-coding-instructions: true` in frontmatter (see analysis — the trap).

## 2. Delivery via embedded Go template

An output style is a file on disk, so new users must not have to hand-author it. Put
the initial value in the Go executable so it ships with install, following the
`internal/templatecmd` / E-1565 pattern: `//go:embed`, lookup order of per-developer
local override -> committed project copy -> embedded fallback, materialized on first
use so users can customize it.

**Open decision to make and document:** does the style install to the user-global
Claude output-styles directory (applies to every session on the machine) or the
project-scoped one (endless only)? Project-scoped is the safer default — a tool
should not silently reshape unrelated sessions — but the user's goal is broader than
one project, so this needs an explicit call rather than a silent default.

## 3. Wiring

Endless has two plausible homes, both currently Python:

- `endless project init` (aliased `register`) — registers the DB row, scaffolds `.endless/`
- the `endless setup` group — `claude-hook`, `prompt-hook`, `shell-helpers`,
  `channel-plugin`, each with a `remove-` counterpart

Decide: a new `endless setup output-style` + `remove-output-style` pair, a step inside
`project init`, or both. Match the group's existing conventions — including the
`remove-` counterpart, which every other member has.

**Go/Python split:** `setup` and `project init` live in Python (`src/.../setup.py`,
`register.py`) while the embed must be Go. Reconcile with E-1486 (remove all Python
SQLite access by porting to Go) rather than working around it — do not add a new
Python-calls-Go shim if E-1486's direction makes the command Go-native anyway.

## 4. Acceptance

- Style file authored and materializable from embed.
- Install and remove paths both work and match `setup` group conventions.
- Installing the style does **not** drop the default `anti_verbosity`,
  `action_caution`, or `task_continuity` sections — verify empirically, do not assume
  the `keep-coding-instructions` default.
- No doc, guide section, or help string references the removed `/output-style`
  command.
- E-1911's appended curated block still renders unchanged alongside the style.
- Degrades legibly when the `outputStyles` safe-mode gate disables custom styles.
