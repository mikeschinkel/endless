# `endless task report <id> --xml=<…>` — structured handoff/report command

Full design rationale: see E-1760 outcome. **Element set grounded by E-1774**
(28-session handoff analysis) — read that outcome for the concern taxonomy and
the reasoning behind every partition below.

## Core idea
Make ceremony **unrepresentable** rather than detectable. The agent's
end-of-session report stops being freeform prose it composes and becomes the
verbatim output of a command it feeds a structured XML payload. There is no
"State outside endless: none" because there is no field to put it in.

This is the durable enforcement layer sitting after E-1758 (handoff-status,
the git-anomaly computation) and E-1759 (spawn-prompt exception rule). The
worked example in E-1760's analysis is the reference specimen — including the
Turn 3 "inventory of the silence" meta-ceremony that a phrase deny-list cannot
catch. Phrase matching is explicitly rejected (too many FP/FN); determinism
comes from removing the freeform surface, not from matching prose better.

## Schema (grounded by E-1774)

E-1774's headline finding: once nothing computable is asked of the agent, the
**"validated-value" middle bucket collapses to empty** — every constrained field
(test result, external state, git facts) is computable or
computable-given-capture. The schema is therefore **computed on one side, gated
free-text on the other, with no editorializing middle.**

### Agent-supplied `--xml` payload — gated free text ONLY
```xml
<report>
  <note kind="anomaly|discovery">MEMORY files edited outside the branch won't land</note>
  <question>Develop go-cambria in a go-pkgs worktree, or directly in the repo?</question>
</report>
```
- `<note>` — repeats; attribute `kind`. The one escape hatch, guarded by the
  per-entry Haiku check (Requirement 4). Real specimens from the sample: "MEMORY
  files edited outside the branch won't land"; "base is behind main"; "E-1648
  landed mid-session"; a rebase-conflict-resolution narrative.
- `<question>` — repeats. Genuine "done, but I need your call on X." Not
  ceremony, so it gets a **different** per-entry check ("a real decision you
  need, or restating settled state?"), not the anomaly check. Reconcile the
  keyword interaction with E-1773's mid-session `FULL STATUS` bypass.
- The normal path is an empty `<report/>` — the command computes and renders
  everything else. Zero free-text entries ⇒ zero Haiku calls.

### Computed by the command and rendered (agent types none of it)
- **git/worktree anomalies** — `monitor.WorktreeAnomalies` (E-1758); empty ⇒
  silence.
- **verify command**, **follow-ups spawned** (link query), **deliverable
  pointer**, **this-task status**, **epic children**, **commit state** —
  computed from existing data and rendered into the relay output.

### Split to follow-ups — NOT this task
- **Structured capture of the report into queryable DB rows → E-1777**
  (brainstorm). E-1771 renders from existing/computed data; it does not build a
  `session_reports` persistence layer.
- **Test-result element (`<tests>` from CTRF) → rides with the capture work
  (E-1777)**; E-1771's first cut does not surface test results.
- **Regression-diffing (worked-then-broke, a VCS-recoverability signal) →
  E-1778** (blocked_by E-1777 — needs captured history to diff against).

### Removed / given NO element (this is the point)
- **Return line** — legacy (`spawner_task` / `return_anchor` decouple). Gone
  from the relay output.
- **External state** — no element. E-1774's search of ~60 sessions found it is
  *pure ceremony* ("no external/CI state"), zero real positives; the rare real
  case rides `<note kind="discovery">`. **Also strike the "flag external state"
  line from the handoff templates** — it manufactures the negative.
- Clean-state confirmations, landed-vs-worktree delta, status recap,
  gitignored-artifact notes, "what changed" prose, self-correction.

## Requirements
1. **Gated free-text payload, not a validated value-set.** Per E-1774 there are
   no validated-value fields — the payload carries only `<note>` and
   `<question>` free-text entries. Rejection is verb-check-style
   (`click.ClickException`, non-zero, anti-rationalization phrasing) but applies
   to a bounced **entry** via the Haiku gate, not to an out-of-set enum value.
   The agent supplies genuinely non-computable facts and open decisions; nothing
   else.
2. **Computes what the tool can compute.** The command calls handoff-status
   (E-1758) for git/worktree facts and resolves commit state, follow-ups,
   status, and epic children. The agent never types these, so it can never dress
   "working tree clean" — it was never asked. (Persisting these facts as
   queryable DB rows, and test-result ingestion, are E-1777 — not this task.)
3. **Self-complete relay output.** The command returns the *entire* final
   message — anomalies (or nothing) + how-to-verify, fully formed. The agent's
   job is "print this, add nothing before or after." This kills the envelope
   leak ("Here's my handoff! 🎉 …").
4. **Per-entry check (Haiku), scoped.** Each free-text entry gets a per-entry
   classifier — anomaly entries: "a real thing the reviewer could not compute,
   or the absence of a problem?"; question entries: "a real decision needed, or
   restating settled state?". It bounces the *entry*, not the message, and fires
   **only when a free-text entry is present** (empty `<report/>` ⇒ zero calls).
   **Haiku is sufficient and fixed** — a bounded per-entry classification, not
   the freeform-paragraph case the schema eliminates by construction. Pick the
   model that works (Haiku) and keep it; it is NOT a config knob (a value that
   works generally has no reason to vary). Swapping the LLM *provider* entirely
   (Codex, Llama, …) may matter someday but is a separate, large feature —
   explicitly out of scope here.
5. **Tunable check wording (user lever).** The check prompt(s) live in a
   user-editable config surface (verbs.jsonl-style precedent), NOT hardcoded in
   the product template. When the user catches the agent freelancing, the user
   tells the agent to improve the wording and the agent edits the *config*, not
   the product. Handoff-message templates may become tunable the same way later;
   start with the check wording. (The model itself is fixed, not tunable — Req 4.)

## Naming
Verb `report`, one positional (`<id>`), payload via `--xml`. Chosen over
`handoff` because this command is the vehicle for *all* end-of-session
reporting, not only the final handoff.

## Status-agnostic
The command is not tied to one status. It is the reporting vehicle at whatever
terminal status the agent reaches (unverified / assumed / completed --outcome).
