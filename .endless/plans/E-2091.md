# Plan — record when a session is waiting on the user

Blocked by E-2105, which gives the session state vocabulary an owning package.
Every step assumes `internal/sessionstate` exists and that Python reads the
vocabulary from it rather than holding a copy.

## 1. Install the hook

Add `Notification` to `CLAUDE_HOOK_EVENTS` in `src/endless/setup.py`.

NOT in `SYNC_EVENTS`: the handler records a state and gates nothing, so it has no
reason to block the harness. Every member of that set is there because something
downstream reads what it wrote within the same turn.

Existing installs need nothing extra. `_repair_missing_hook_events` already adds
an endless-go entry for any hooked event that has none, precisely so a machine
whose install predates an event still gains it — verified, not assumed.

## 2. The state

Add `Prompted` to `internal/sessionstate` and classify it into all five groups,
which the package makes unskippable:

| Group          | Member? | Why |
|----------------|---------|-----|
| `All`          | yes     | `working, prompted, idle, needs_input, ended` — lifecycle order; beside `working` because it is a mid-turn state |
| `Live`         | yes     | the session is running |
| `MayWrite`     | **yes** | decided 2026-09-01; see the analysis |
| `AwaitsHuman`  | yes     | it is the definition of the group |
| `DisplayOrder` | first   | `prompted, working, needs_input, idle, ended` |

Label `prompted`. Glyph the warning sign E-1976's board already uses for the
rank; it measures one column under go-runewidth, which the vocabulary's glyph
test asserts for every member.

Transition rows: `any -> prompted` (Notification / `monitor.PromptSession`) and
`prompted -> working` (see §4).

`AwaitsHuman` is the group that carries this task's definition of waiting: after
this change it holds `idle`, `needs_input` and `prompted` — every state in which
the session has paused for the user, question or no question. Anything that needs
to ask "is this session waiting on me" asks that group, not a list of states.

## 3. The handler

`case "Notification":` in `internal/hookcmd/claude.go`, reading the payload's
`notification_type` field and acting on exactly two values:

- `permission_prompt` -> `monitor.PromptSession(sessionID)`, a new helper beside
  `IdleSession`/`EndSession` writing the `prompted` state and refreshing
  `last_activity`.
- `idle_prompt` -> `monitor.IdleSession(sessionID)`. It means the input prompt
  sat untouched for 60 seconds, which is what `idle` already says. Idempotent on
  a session already idle.

Every other value writes no state. `notification_type` carries at least a dozen
documented values — auth, elicitation, quota, agent-team — and a notification
Endless does not model must not move the session. An unrecognised value is also
the shape a harness change arrives in.

`claudePayload` gains `NotificationType string` with the `notification_type` tag.

`monitor.ParseTranscript` is NOT called here: Notification is not a turn boundary
and carries no new messages.

## 4. Clearing it

`prompted` returns to `working` on the session's next activity, via
`monitor.ResumeFromPrompt(sessionID)` which updates only when the current state
is `prompted`, so it can never demote a session that moved on another way.

Called from `PostToolUse` (the approved tool completed) and `UserPromptSubmit`
(the user typed instead). `Stop` needs no change: it writes `idle`
unconditionally, correct for a turn that ended with a prompt outstanding.

Deliberately NOT folded into `TouchSession`, which never clobbers a live state;
making it the exception for one value is how a general helper starts carrying
special cases.

Because `prompted` is in `MayWrite`, a missed clear costs a stale glyph until the
next Stop. It cannot refuse anyone.

## 5. Stop making new `needs_input` sediment

`monitor.InitSession` writes `needs_input` as a row's initial value, and the
revive-an-ended-row CASE (`monitor.TouchSession`, `internal/events/executor.go`)
writes it on any incoming hook. Neither means a person is being waited on.

Both become `idle`, which is what they actually mean: the session exists and is
not doing anything. `needs_input` is then written by nothing, and means only what
the declaration gate says.

The 34 existing rows are NOT migrated. They are surfaced by §6 so they can be
resolved deliberately; retiring them automatically is the opposite of what
revealing them is for.

## 6. Reveal them on the board

`internal/monitor/project_status.go`: `boardSessionStates` is deleted, and the
session query filters on `sessionstate.SQLList(sessionstate.Live)`. E-1976's
exclusion of `needs_input` goes with it, along with its comment.

`internal/projectstatuscmd/board.go`: `classify()` routes `prompted` to
`actWaiting`, alongside the existing `needs_input` arm. Both are waiting on the
user; the board's age column already distinguishes a live prompt from a
two-month-old row on sight, which is what that column is for.

## 7. What this does NOT change

The board's RANK ORDER. `idle` sits sixth of seven today, which under this
task's definition of waiting is arguably too low — but that is a display
question, and the board's UI is being reshaped separately. Recognising state and
displaying it are orthogonal; this task does the first, completely, and leaves
the second alone so the redesign is not pre-empted.

No classification of how a turn ended, no reading of the final assistant message,
and no dependency on the minimizer, which is disabled and out of this task's
critical path by decision.

## 8. Python

None, if E-2105 landed as planned: the `--state` choice and the glyph map both
come from the registry, so `prompted` flows through. Verify rather than assume —
`endless session list --state prompted` must be accepted and must render the
warning glyph.

## 9. Migration

None. No row carries `prompted` today and no existing value changes meaning.

## 10. Verification

`.endless/tasks/e-2091/verify.sh`, sourcing `_harness.sh`:

1. Fail-fast unit gate: `internal/sessionstate`, `internal/hookcmd`,
   `internal/monitor`, `internal/projectstatuscmd`, and the Python suite.
2. `Prompted` is in `MayWrite` — asserted directly, because it is the decision
   the design turns on and its absence is a wedged session, not a wrong glyph.
3. The declaration gate admits a prompted session: drive `sessionMayWrite` with
   a prompted session holding a task and assert it may write.
4. `AwaitsHuman` holds `idle`, `needs_input` and `prompted` — the vocabulary's
   statement of what waiting means, pinned so a later edit is deliberate.
5. State machine round trip: `PromptSession` then `ResumeFromPrompt` yields
   `working`; `ResumeFromPrompt` on a working session is a no-op; `Stop` from
   `prompted` yields `idle`.
6. The handler routes `permission_prompt` and `idle_prompt` and IGNORES a third
   value, asserted against synthetic payloads rather than a live harness.
7. No writer produces `needs_input`: a sweep asserting `InitSession` and the
   revive CASE write `idle`, plus a seeded SessionStart landing on `idle`.
8. `setup.py` installs seven events with `Notification` among them and not in
   `SYNC_EVENTS`, and a settings file carrying only the old six is repaired to
   seven rather than reported correct.
9. End to end against a seeded throwaway database: a prompted session renders as
   the board's first row, and a `needs_input` session renders rather than being
   suppressed.
