Mechanism (three parts):

1. Invert the default. The task report output IS the sanctioned user-facing message (already shown to the user as tool output). Move the two legitimate exceptions INTO the report so no prose outside it is ever justified:
   - the task's single verify command becomes a report field;
   - genuine open decisions/blockers go through the report's --json notes/questions channel (already E-1803's model).

2. Record the checkpoint. The report command marks the session turn as a verbatim-relay checkpoint and stores the exact sanctioned text.

3. Gate at Stop. A Stop hook compares the agent's actual final message to the sanctioned text; anything beyond it returns decision:block with a reason the user also sees ("appended N lines beyond the report; resend verbatim"). Compliant = empty or exactly-sanctioned; prose becomes the caught exception, not a discretionary default.

Keystone: routing the verify command and open decisions through the report as FIELDS is what collapses the Stop-hook check from an intractable 'is this prose a legitimate question or a banned recap' judgment into a hard equality check. Without it the gate has false positives; with it, prose-outside-the-report is always a violation.
