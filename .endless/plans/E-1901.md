# Plan — E-1901: enforce verbatim report relay with a Stop-hook gate

Rebased onto main (E-1803 landed as `5dcdc2bf`), so `taskReportRe`, the
PostToolUse relay nudge, and `reportChannelRule` are all present and are reused,
not reinvented.

## Decisions taken (were open in the plan)

1. **Verify command enters via the `--json` payload** as a `verify` key —
   symmetric with `notes`/`questions`, no schema change on `tasks`, agent-supplied
   at report time. NOT Haiku-gated: a command is a command, not prose.
2. **Empty report renders a fixed sanctioned line, `Nothing to report.`** — not
   silence. Silence is indistinguishable from a stalled agent; one fixed line
   proves the turn ended deliberately and states the null result. Checkpoint-
   neutral (reads correctly mid-session and at session end).
3. **The comparison input is `last_assistant_message`**, the Stop-specific
   payload field. The Claude Code hooks reference explicitly says hooks needing
   the final assistant text must use it rather than reading the transcript,
   which lags. This removes the transcript-parse race entirely.

## Mechanism

### Part 1 — invert the default (Python)

`src/endless/report_cmd.py`, `report_prompts.py`, `cli.py`:

- `--json` accepts a third key, `verify`: a single non-empty command string.
  Rejected like the others on the wrong type; no Haiku call.
- Split today's single `_render_facts` into two:
  - `_render_sanctioned` — the user-facing block: `Verify:` (leads; it is the
    most actionable line), follow-ups, epic children, notes, questions.
  - `_render_agent_notes` — the worktree-anomaly advisory. This CANNOT be in
    the sanctioned block: it is explicitly labelled "for you — surface only if
    unexpected", so forcing its relay is wrong and excluding it from the block
    while leaving it inside would bounce any agent that obeys it. It renders
    OUTSIDE the markers, and the steer tells the agent that an unexpected
    anomaly is re-run material (`--json` note), never appended prose.
- Empty sanctioned block → substitute the `nothing-to-report` prompt text.
  Because the empty case now has a sanctioned string, the two rendering paths
  collapse into one: one steer, one comparison, no special case.
- Rename the `steer-empty` prompt to `nothing-to-report`. Its role changed from
  *steering the agent* to *being the sanctioned message*, so the old name would
  misdescribe it. Safe: no override file exists at either the machine or project
  layer, so nothing depends on the old name.
- `STEER` gains explicit `----- BEGIN REPORT -----` / `----- END REPORT -----`
  markers around `{facts}` so "verbatim" has an unambiguous extent, and names
  the gate so the agent knows the bounce is coming.

### Part 2 — record the checkpoint

- `internal/gatekind`: add `GateKindRelay = 2` (slug `relay`).
- `internal/schema/schema.sql`: seed the `gate_kinds` row; add
  `session_gates.sanctioned_text TEXT` and `session_gates.bounces INTEGER NOT
  NULL DEFAULT 0`. Plus `internal/schema/changes/e-1901-relay-gate.sql` for the
  populated real DB at land time.
  `session_gates` is the right home rather than a new table — it is already "a
  pending interception for a session" with a `kind_id` discriminator and named
  per-kind subject columns. Its doc comment (which says gates block at
  PreToolUse) is broadened to cover a Stop-blocking kind.
- `internal/monitor/session_gate.go`: `SetRelayCheckpoint`,
  `PendingRelayCheckpoint`, `ClearRelayCheckpoint`, `BumpRelayBounce` —
  mirroring the revisit helpers, including supersede-on-insert.
- `internal/sessionquerycmd`: `relay-checkpoint --session-id N`, sanctioned text
  on **stdin** (not argv — a report block is unbounded and would hit quoting and
  argv-length limits).
- `report_cmd.report_item` resolves the session via the existing
  `_current_endless_session_id()` and records. Best-effort: an unresolved session
  means no checkpoint and no gate, never a failed report.

### Part 3 — gate at Stop

- `claudePayload` gains `LastAssistantMessage` and `StopHookActive`.
- New `internal/hookcmd/relay_gate.go` holding the pure, DB-free comparison so
  it is unit-testable without infrastructure.
- Normalization before comparison, applied to both sides: trim trailing
  whitespace per line, drop blank lines at both ends, collapse blank runs, drop
  marker lines, drop lines that are only a code fence. Fence-dropping is
  deliberate: an agent wrapping the verify command in ``` is formatting, not
  prose, and bouncing it would be a false positive that teaches the agent the
  gate is noise.
- Compliant = normalized-empty OR normalized-equal. Otherwise emit
  `{"decision":"block","reason":…,"systemMessage":…}`. Both fields carry the
  violation because they go to different audiences — `reason` to Claude,
  `systemMessage` to the user — which is what "names the violation where both
  agent and user see it" requires.
- Loop guard: `bounces` is incremented per block and capped at 2, after which
  the gate clears and lets the turn end. `stop_hook_active` is undocumented, so
  it is a secondary signal only; the counter is the primary guard and is
  deterministic.
- Cleared on `UserPromptSubmit` — a new user turn supersedes an unconsumed
  checkpoint, so a checkpoint can never leak into a later turn (this is also
  what keeps `FULL STATUS` unblocked).

### Part 4 — Stop must be synchronous

`Stop` currently sits outside `SYNC_EVENTS` in `src/endless/setup.py`, so it is
installed `async: true` — and an async hook cannot block. Two changes:

- Move `Stop` into `SYNC_EVENTS`.
- `setup_claude_hook` currently early-returns when a hook is already installed,
  so no existing install would ever get the fix. Add an idempotent repair that
  corrects `async` flags that disagree with `SYNC_EVENTS` and reports what it
  changed.

The worktree's `.claude/settings.json` mirrors the user's global file, so it
picks the flag up once the global is repaired and `just claude-settings-init`
re-runs.

## Verification — `tests/tasks/e-1901-verify.sh`

Fully scripted, fail-fast on the unit contract, single entry point:

- Go unit tests: the normalization/verdict matrix (verbatim passes; appended
  prose bounces with the right count; empty passes; fences and markers tolerated),
  the block-response shape (both `reason` and `systemMessage` present), and the
  bounce cap.
- Python tests: `verify` payload accepted and rendered leading the block;
  anomalies rendered outside the markers; empty report renders `Nothing to
  report.`; the renamed prompt resolves.
- `setup.py`: `Stop` is in `SYNC_EVENTS`, and the repair flips a stale async
  entry.
- End-to-end through the real CLI → worktree endless-go → sandbox DB: run
  `endless task report` and assert a relay checkpoint row lands with the exact
  sanctioned text.

## Honest ceiling (carried from the analysis, not softened)

This is a hard gate on the report checkpoint, not a guarantee the urge never
fires: a re-prompted model can comply now and drift on a later turn, and the
bounce cap means a determined violation eventually lands. What changes is the
cost — appending stops being free and becomes "publicly named and bounced,
every time."
