Mechanism (three parts):

1. Invert the default. The task report output IS the sanctioned user-facing message (already shown to the user as tool output). Move the two legitimate exceptions INTO the report so no prose outside it is ever justified:
   - the task's single verify command becomes a report field;
   - genuine open decisions/blockers go through the report's --json notes/questions channel (already E-1803's model).

2. Record the checkpoint. The report command marks the session turn as a verbatim-relay checkpoint and stores the exact sanctioned text.

3. Gate at Stop. A Stop hook compares the agent's actual final message to the sanctioned text; anything beyond it returns decision:block with a reason the user also sees ("appended N lines beyond the report; resend verbatim"). Compliant = empty or exactly-sanctioned; prose becomes the caught exception, not a discretionary default.

Keystone: routing the verify command and open decisions through the report as FIELDS is what collapses the Stop-hook check from an intractable 'is this prose a legitimate question or a banned recap' judgment into a hard equality check. Without it the gate has false positives; with it, prose-outside-the-report is always a violation.

## Integration with E-1803

E-1803 ships the compose-time half of this feature (a relay nudge + the
coverage rule) and is landing now; once it lands you rebase onto it. Reuse what
it built rather than reinventing or colliding with it:

- **Detection already exists.** `internal/hookcmd/claude.go` has `taskReportRe`
  — it matches a Bash command that actually RUNS `endless task report`, anchored
  to a command position so the phrase appearing as an argument (a commit
  message, `echo`, `grep`) does not misfire. It drives a `PostToolUse` branch
  that emits the relay-verbatim nudge. Reuse `taskReportRe` for step 2's "record
  the checkpoint"; do NOT add a second, drifting matcher. (You will also edit
  `claude.go`, so you rebase onto these additions.)
- **The Stop gate layers on the nudge, it does not replace it.** Arm 1's
  `PostToolUse` additionalContext ("relay verbatim, add nothing") stays as the
  compose-time reminder that helps the agent comply on the first try and avoid
  the bounce; this task's Stop-hook block is the enforcement layer at turn end.
- **Sanctioned text = the fact block, not the steer prompt.** `task report`
  prints a *steering prompt* ("Report the following… add nothing") that the
  agent must NOT relay. Step 2 must store the facts-to-relay, separate from that
  wrapper — otherwise the Stop equality check compares against the wrong string.
- **The empty-report case is now the common one (E-1880).** Post-E-1880 a clean
  session's report fact block is empty and steers the agent to say nothing. Your
  equality gate needs a defined sanctioned message for that case (e.g. the
  deliverable one-liner + the verify command) or it has nothing to match. This
  is the sharpest open design point for the keystone.
