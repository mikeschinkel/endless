# Documents System: Implementation Plan

## Prerequisites from E-799

- **E-803** (Kairos) — documents use same timestamps
- **E-804** (event envelope) — document event kinds extend same vocabulary
- **E-805** (Go event writing) — document mutations go through Go
- **E-807** (projection) — document projection uses same machinery
- **E-810** (Lexorank) — section ordering uses Lexorank

E-823 (schema design) can start as pure design work in parallel with event-sourcing.

## Critical Path

```
E-823 (schema design)
  → E-824 (event kinds + projection)
    → E-827 (CLI commands) ← MVP milestone
      → E-851 (dashboard views)
      → E-825 (proposal/review workflow)
        → E-826 (conflict surfacing)
      → E-828 (apply-from-chat bridge) [later]
      → E-829 (MCP tools) [later]
      → E-830 (markdown import) [later]
    → E-841 (ADR workflow) [once CLI works]
      → E-582 (capture Q&A as decisions)
```

## MVP

**E-823 + E-824 + E-827** = minimum useful documents:
- Create a document with sections
- Update individual sections via CLI
- View documents in dashboard (E-851)
- Event history preserved

Proposal/review (E-825) and conflict surfacing (E-826) matter when multiple actors edit the same document — important but not MVP.

## Subtask Details

- **E-823** (tier 2): Schema follows task patterns. Stable local_id + global_id. Sections with stable identifiers, Lexorank positions.
- **E-824** (tier 2): doc.created, doc.section_added/updated/renamed/moved/removed, doc.archived. Extends existing projection machinery.
- **E-827** (tier 1): endless doc add, show, section-update, section-add, apply-from-file, history. Straightforward once schema/events exist.
- **E-851** (tier 1): Document list in project view, detail with rendered sections, edit history timeline, accept/decline controls.
- **E-825** (tier 3): doc.section_replacement_proposed/resolved. Dashboard diff view. State machine for proposals.
- **E-826** (tier 3): Three-way merge for concurrent section edits. Structural conflicts (delete vs update). Same pattern as task conflicts (E-815).
- **E-828** (tier 2): Markdown diffing — compare file to current doc state, emit section-level events for differences.
- **E-829** (tier 2): MCP tool patterns exist from task tools. Deliberately narrower than CLI.
- **E-830** (tier 1): Parse markdown by headers, emit doc.created + doc.section_added events per section.
- **E-841** (tier 4): Needs discussion — standard ADR sections, task integration, review workflow.

## Gaps to Track

- **Document-task linking**: ADR that references tasks it affects. Deferred but valuable.
- **Claude web output convention**: Not a code task but a workflow discipline to document.
