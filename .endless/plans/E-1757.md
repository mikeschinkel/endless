# (b) Build the unified `project init` command — PLAN

Parent epic: the `project` command group. Blocked by child (a) (the `project` group
must exist first).

## Decision (from the epic)
Unify DB registration and file setup into ONE idempotent `project init`:
- Ensures the project's DB row (today `register_project` in `src/endless/register.py`).
- Scaffolds on-disk files: `.endless/config.json` (existing) + the `.gitignore`
  entries (see the `/tmp`→`.endless/tmp` task, which adds gitignore-scaffolding).
- `project register` becomes an alias for `project init` (same behavior).
- Re-running is always safe (scaffold only what is missing; don't clobber).

## Canonical `.gitignore` set to scaffold
- `.endless/worktrees/` and `.endless/tmp/` (definite).
- `.endless/worktree.json`, `.endless/worktree.lock` (kept — see ADR ED-1530).
- NOT `.endless/sessions/` — child (c) prunes it; land (c) before this freezes the
  set so the obsolete entry is never scaffolded into new projects.

## Deliverable — verify script
Generate `tests/tasks/e-<id>-verify.sh` (shape per `tests/tasks/e-1577-verify.sh`):
`project init` on a throwaway git repo creates the DB row AND scaffolds
`.endless/config.json` + the canonical `.gitignore` set; re-running is idempotent
(no dup rows, no dup gitignore lines); `project register` behaves identically. On
completion, set `unverified` and hand off exactly:
`esu && ./tests/tasks/e-<id>-verify.sh`.
