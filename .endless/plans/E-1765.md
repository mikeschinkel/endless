# Render `submitted` distinctly from `ready` (a "review" action, not spawnable)

## Context
E-1648 added the `submitted` status (spec-complete, awaiting approval) but left it rendering
identically to `ready` on two surfaces, so a submitted task LOOKS spawnable even though it is
not approved. The gate itself holds — `task next` excludes submitted and a background session
is refused from claiming non-`ready` work — but the visual signal contradicts the gate.
Surfaced 2026-07-10 while the user reviewed E-1764 (a submitted task that appeared
"ready to spawn").

Current inconsistency across surfaces:
- `task next`            → excludes submitted (correct)
- `claim` (background)   → refuses non-ready pickup (correct)
- `session status`       → classify maps submitted → `actDo` (`▶ do`) — WRONG, looks spawnable
- web "next available"   → includes submitted (project_detail.templ) — WRONG, looks available

## Deliverable 1 — distinct action in session status
`internal/sessionstatuscmd/session_status.go`: add a distinct action instead of folding
submitted into `actDo` — a new `actReview` with its own glyph and the label **`review`** (a
prompt to the user to review/approve, mirroring the `plan` / `verify` verb style). Update:
- `classify` — drop submitted from the `actDo` case; return `actReview` for submitted.
- the action enum (mind sort-rank placement — the enum is sort-ordered) and `icon()`.
- the legend and `TestActionIcons`.
- add a `session_status_test.go` row asserting `submitted → actReview`.
- `tree.go doPlanIDs` (currently gathers actDo/actPlan) — decide whether the review action
  belongs in that backlog tree.

## Deliverable 2 — web dashboard
`internal/web/pages/`: reconcile submitted so it is not shown as plain "next available"
alongside ready — a distinct badge/label ("awaiting review") or a separate grouping. Edit the
`.templ` source and regenerate with `just build` (never hand-edit `_templ.go`). Leave
`task next` exclusion and the claim-gate as-is (already correct).

## Deliverable 3 — per-task verify script
Create `tests/tasks/e-1765-verify.sh`, modeled on the established convention (`tests/tasks/
e-1648-verify.sh` / `e-1729-verify.sh`): a self-isolating bash script (throwaway repo + temp
`XDG_CONFIG_HOME`/`XDG_CACHE_HOME`, no real DB/ledger touched), `set -u`, section/pass/fail/
summary helpers, `ALL PASSED` on success, exit 0/1/2. Prepend `<worktree>/bin` to PATH so the
Python event bridge execs the candidate binary. Coverage:
- `go test ./internal/sessionstatuscmd/` passes with the new `submitted → actReview` row.
- grep asserts `classify` no longer maps submitted to `actDo` and DOES map it to `actReview`.
- the `review` label + its glyph are present in `icon()`/legend.
- web `.templ` source renders submitted distinctly (grep the submitted arm / badge).
- regression: `go test ./internal/events/ ./internal/monitor/`.
