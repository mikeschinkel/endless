# E-1687 brainstorm synthesis — run candidate build from a bare worktree shell

## Context

The point of a self-dev worktree is to test the worktree's changes. But from a bare
(non-Claude) tmux sibling pane inside the worktree, the CLIs silently run **main's** code:

- **`endless` (Python)** → `~/.local/bin/endless`, a uv-tool console script
  (`from endless.cli import main`) whose venv holds an **editable install pointing at the
  MAIN checkout**. So it imports main's `src/` regardless of cwd. New flags in the worktree
  (e.g. `endless session next --tree`, E-1684) error `No such option` until landed. This is
  the case that actually bites.
- **`endless-go`** → `/usr/local/bin/endless-go`, a symlink to `main/bin/endless-go`. Even
  though the worktree-create hook copies a candidate to `<worktree>/bin/endless-go`, bare
  `endless-go` on PATH still resolves the main symlink. Only `./bin/endless-go` reaches the
  candidate (and E-1368 makes it self-detect the sandbox DB from cwd).

DB routing (which ledger) was solved by E-1368/E-1281/E-1513 self-detection. This brainstorm
closes the parallel gap for **which code executes**.

## Decisions locked (interview, 2026-07-01)

1. **Automatic cwd self-re-exec is the default; `esu` continues to work** for session binding.
   A plain `cd`-into-worktree pane must route to the candidate with zero ceremony.
2. **Both CLIs in scope** — Python `endless` *and* bare `endless-go`. One coherent fix,
   symmetric mechanism.
3. **Brief stderr notice on re-exec** — one dim line so it's never unclear which code ran;
   stderr keeps stdout clean for piping.

## Design (for the spawned implementation task)

A pre-parse self-re-exec in each CLI's entry point, gated on the same predicate that already
gates DB self-detection, guarded against re-exec loops, mirroring E-1368.

**Fire predicate (reuse existing symbols, don't reinvent):**
- cwd matches the canonical worktree path segment — Python `config._WORKTREE_PATH_RE`
  (`src/endless/config.py`, the `/.endless/worktrees/(e-NNN)` regex); Go's equivalent in
  `cmd/endless-go/main.go`.
- AND `config.project_is_self_dev(project_root)` is true (`src/endless/config.py:118`). This
  keeps downstream projects (self_dev unset) from ever re-exec'ing — only endless's own
  worktrees route. Same opt-in boundary as the sandbox.
- Worktree root = cwd truncated at the regex match; `src = <root>/src`,
  `gobin = <root>/bin/endless-go`.

**Python** — shim at the top of `AgentAwareGroup.main()` (`src/endless/cli.py:186`, the Click
`Group.main` override that already consumes `--db` *before* Click parses). Placing the re-exec
there means it runs before argument parsing, so the **worktree's** Click parses the args and
new flags like `--tree` work (no "No such option"). Mechanism: `os.execve(sys.executable,
[sys.executable, sys.argv[0], *argv], env)` with `PYTHONPATH=<worktree>/src` prepended and the
loop-guard env var set. Keeping `sys.executable` (the uv-tool venv python) means deps still
resolve from main's venv; only the `endless` package source flips to the worktree.
- Python "candidate" is always present (it's the checkout's `src/`) — **no not-built case**.

**Go** — shim at the top of `main()` in `cmd/endless-go/main.go`, alongside the existing
E-1368 sandbox self-detection (the binary already has cwd-awareness). If cwd is a self-dev
worktree and `os.Executable()` is not already `<worktree>/bin/endless-go`, `syscall.Exec` that
binary. If the candidate binary is **absent**, emit a loud stderr warning and continue as main
(don't block) — the copy is the hook's job and the user expects it present.

**Loop guard (both):** an env var, e.g. `_ENDLESS_CANDIDATE_REEXEC=1`, set before exec and
short-circuiting on entry. Symmetric across Python and Go.

**Stderr notice (both):** one dim line on re-exec, e.g. `endless: candidate build (e-NNN)`.

**Known limitation to note, not solve here:** a **stale** `<worktree>/bin/endless-go` (agent
edited Go but hasn't `just build`) re-execs stale candidate code. The stderr notice reveals
*which* binary ran but not its freshness. Python has no analog (source is live). Flag as a
possible follow-up (mtime compare of src vs binary), don't block on it.
