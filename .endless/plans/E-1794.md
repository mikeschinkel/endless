# E-1794 (reopened) — the gate still can't tell a leading slash from a path

## What the first pass got wrong

The first pass narrowed "is this a path" to three lexical signals: absolute,
an explicit ./ ../ ~/ prefix, or a filename extension. It defined absolute as
"a leading slash followed by a path" — which fixed a lone '/' but left every
one-segment leading-slash token reading as an absolute path.

So these are all refused today, none of which is a path:

    /whats-left            a slash-command name in a lesson
    /loop  /code-review    same, and there are dozens more
    /tmp                   a bare well-known directory named in prose

The last one is the sharpest evidence: the gate's own refusal text says "a /tmp
path is lost when a worktree drops", and that sentence cannot be written into a
lesson or a decision by the tool that emits it.

## It is one defect, not three verbs' worth

Reported against `lesson write`, and suspected of `decision add/update`. Both
confirmed — along with `task add/update`, `epic`, and the status-transition
verbs. That is not three bugs: every inline/file flag pair funnels through
`_resolve_content_flag`, which is the single composition point the gate was
deliberately built on. One fix there covers all of them, and any fix made
per-verb would be wrong by construction.

## The rule

Three tiers, cheapest and most certain first.

1. LEXICAL, deterministic, no I/O — decides everything unambiguous:
     - two or more segments      -> a path      (/tmp/x.md, /Users/x/plan.md)
     - one segment + extension   -> a path      (/plan.md)
     - nothing after the slash   -> not a path  (/, //)
   This is where every real mis-passed file lives, so the case the gate exists
   to catch never depends on anything beyond the string itself.

2. AMBIGUOUS, and only this: one segment, no extension. /tmp vs /whats-left.
   A bounded, mostly-static set. Ask the model once, the way the verb gate at
   task_cmd._check_verb_via_haiku already asks whether a word is a verb:
   hook-suppressed `claude -p` via internal_claude.run_internal_claude, low
   effort, short timeout, model from config.internal_model.

3. CACHE the verdict, the way an auto-registered verb is cached. Reuse the
   layered project-over-machine JSONL that matchers already implements
   (project_verbs_path / machine_verbs_path), so a project's answers are
   committed and shared rather than re-derived per machine. This is what makes
   the model call rare AND makes the answer machine-independent — the objection
   that rules out a bare filesystem existence probe, which would answer
   differently on a box with no /Users and fail open on exactly the paths the
   gate is for.

## Degrade direction — this differs from the verb gate, on purpose

The verb gate degrades CLOSED: a timeout or missing binary falls through to the
standard refusal. This gate must degrade OPEN for the ambiguous class only.

Reason: failing closed here re-creates the bug being fixed (/whats-left refused
whenever the model is unreachable), while failing open admits at worst a bare
one-segment absolute in prose — which carries none of the harm the gate names,
since "a /tmp path is lost when a worktree drops" requires a file under /tmp,
i.e. two segments. Tiers 1 and 3 are unaffected: they never call out.

## Must not regress

Everything the first pass protected, all of it lexical and none of it reaching
tier 2:

    /tmp/plan.md  ./o.md  ~/d.txt  plan.md  docs/guide/index.md   still refused
    absolute paths embedded in prose                              still refused
    --allow-path still per-path, not a blanket
    pytest/uv, a named '/', type / subtype                        still accepted
