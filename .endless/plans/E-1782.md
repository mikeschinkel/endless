# Document `endless task report` + report-by-default posture in `endless guide tasks`

## Context
E-1771 shipped `endless task report <id>` — it computes the facts and prints a
terse just-the-facts steering prompt the agent relays verbatim. E-1773 wired the
report-by-default posture and the `FULL STATUS` bypass into the spawn **handoff
templates**. But `endless guide tasks` — the standing reference every session
reads — has **zero** mention of the command or the posture (grep: no `report`,
no `--json`, no end-of-session-reporting guidance). So a non-spawned session, or
any session consulting the guide rather than a handoff, never learns the command
exists. This closes that guide-coverage gap. Surfaced during E-1773; kept
separate to keep that task focused on the templates.

## Source of truth
`endless guide tasks` renders the hand-authored `docs/guide/tasks.md`. The
agent-facing command/topic → section cross-reference and the `docs/guide/index.md`
lookup table are **generated** — regenerate them after editing (see step 3).

## Scope (what to add)
A short narrative subsection in `docs/guide/tasks.md` — natural home is right
after `## Status transitions` (line ~165), since reporting pairs with reaching a
terminal status; a new `## Reporting to your user` section is clean. It states:

1. **The command exists and what it's for** — `endless task report <id>` produces
   an end-of-session / status report: it computes status, follow-ups, children,
   and worktree state, and prints a steering prompt to relay **verbatim, no
   ceremony**. Status-agnostic; it does not change the task's status.
2. **Report-by-default posture** — end-of-session and status reports route through
   this command and are relayed as-is, not composed as freeform prose. The normal
   path takes **no payload**.
3. **Anomaly escape hatch, by reference only** — `--json` / `--json-file` carry
   genuinely out-of-band notes or open questions. **Do not inline the schema** —
   point at `endless task report --help`, the single canonical (drift-proof) home
   for the exact payload shape.

Narrative only — no schema duplication. Keep it a few sentences plus one example
invocation, matching the density of the surrounding sections.

## Steps
1. Add the subsection to `docs/guide/tasks.md`.
2. If a `## Reporting` concept also belongs in the `index.md` happy-path
   (step 5–6 "report completion" already gestures at it), tighten that to name the
   command — optional, only if it reads naturally.
3. Run the **`regenerate-guide`** skill to rebuild the command→section
   cross-reference + `index.md` table so `endless task report` resolves to the
   tasks section. This is the generation step — do not hand-edit the generated
   table.

## Verification

`tests/tasks/e-1759-verify.sh` harness) OR a direct assertion:
- `endless guide tasks` output contains the report-command coverage (e.g. greps
  for `endless task report` and the report-by-default wording), and
- the generated cross-reference resolves `endless task report` to the tasks
  section (assert the regenerated map/index includes it).
Doc-only change — no runtime behavior to exercise beyond the rendered guide.

## Out of scope
- The handoff-template wiring (done in E-1773).
- Any change to the `endless task report` command itself or its `--help` text.
