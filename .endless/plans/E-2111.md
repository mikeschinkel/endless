# Plan — one writer computes the unlanded verdict, every reader reads it

## The decision

The exact "does this branch hold work the base lacks?" verdict stops being
computed by its consumers and becomes **derived state owned by one background
job**. Consumers read a per-repo file cache. The reaper comes off the
PreToolUse/PostToolUse hook path entirely and becomes a job of its own.

This is one change, not two, because the reaper's periodic-sweep cost and the
monitor's continuous fan-out are the same defect: *the verdict is recomputed
from scratch by every consumer on every tick, with no shared derived state.*
Under ED-1550 §3 that is one cause, so it is one task.

## The invariant this rests on, and how it is checked rather than trusted

The unlanded set can only SHRINK as the base branch gains commits. The probe
asks, for each branch commit since the fork, whether a matching commit exists on
base since the fork. Adding commits to base only adds candidates to match
against: a commit that already matched keeps its match, and one that did not may
acquire one. Nothing that matched becomes unmatched.

Therefore:

- **A verdict of ZERO unlanded stays true as long as the BRANCH tip does not
  move**, no matter how far the base advances.
- **A verdict of N>0 is only valid while BOTH tips are unchanged**, because base
  movement can shrink it.

The invariant assumes the base is append-only. That assumption is CHECKED, not
trusted, by a repo-level watermark (below). An amended, reset, or force-pushed
base is detected and flushes the cache; a `--amend` on a task BRANCH moves the
branch tip and self-invalidates that one entry.

Two things the invariant deliberately does not cover, both pre-existing and
neither introduced here: work that landed and was later REVERTED still reads as
settled (the original landed commit is still in base's history to match
against), and uncommitted/untracked files are not commits at all — they are a
separate probe that stays live.

## The cache

**Location.** `<git-common-dir>/info/endless/unlanded/`

`git rev-parse --path-format=absolute --git-common-dir` from inside any linked
worktree resolves to the main checkout's `.git`, so all worktrees of a repo
share one cache directory for free. Verified on git 2.52.0. `.git/info/` is
untracked, never pushed, per-clone, and survives `git gc` — the correct home for
derived state that describes this clone. No database involvement, so worktree
sandbox routing does not apply.

**One file per worktree**, named `<worktree-basename>-<8 hex of sha256(abs
path)>.json`. Per-file rather than one document so concurrent writers never
collide, pruning is an unlink, and a corrupt entry damages one worktree.

```json
{
  "version": 1,
  "worktree": "<absolute worktree path, stored for verification>",
  "branch_tip": "<OID of the worktree's HEAD when computed>",
  "base": "main",
  "base_tip": "<OID of base when computed>",
  "unlanded_count": 0,
  "unlanded_log": ["<short-sha> <subject>", "..."],
  "probe_error": "",
  "computed_at": "2026-09-09T04:12:33Z"
}
```

`unlanded_log` stays bounded by the existing `unlandedLogLimit`. `probe_error`
carries a failed compute so a reader reports undetermined rather than silently
clean — the fail-closed rule from E-1940 is preserved through the cache.

**Watermark**, `<git-common-dir>/info/endless/unlanded/watermark.json`:

```json
{ "version": 1, "base": "main", "base_tip": "<OID>", "verified_at": "..." }
```

**Validity protocol**, run once per process (not per row):

1. One call to `git worktree list --porcelain` yields every worktree path, every
   worktree's HEAD OID, and the base branch's own tip. **Measured: 14ms for 135
   worktrees on this repo.** This is the entire enumeration and tip-reading step.
2. Compare the base's current tip to `watermark.base_tip`.
   - Equal, and `watermark.base` equals the resolved base name → every entry is
     valid per its own rule below.
   - Different → `git merge-base --is-ancestor <watermark.base_tip> <current>`.
     - exit 0 → base only appended. Entries with `unlanded_count == 0` remain
       valid; entries with `unlanded_count > 0` are stale. The job advances the
       watermark; readers never write it.
     - exit 1 → base history was rewritten. Every entry is invalid; the job
       deletes the directory's entries and recomputes.
     - any other exit → fail closed. Treat every entry as a miss.
   - `watermark.base` differs from the resolved base name (config edit) → full
     invalidation, same as exit 1.
3. Per entry: valid iff `branch_tip` equals the worktree's current HEAD, AND
   (`unlanded_count == 0` OR `base_tip` equals the current base tip).

## Two jobs, not one

Different cadences, so splitting them is simpler than one job with internal
scheduling. Both follow the existing `internal/backupjob` shape — own package,
`init()` registers, `Name`/`Schedule`/`Run`.

**`internal/unlandedjob`** — name `worktree-unlanded`. `Interval: 60s`,
`LeaseTTL: 15m`. Runs the validity protocol, recomputes every invalid entry,
writes each atomically (temp file + rename in the same directory), advances the
watermark, and unlinks entries for worktrees git no longer lists. A cold pass
over 135 worktrees is ~1-2 min single-threaded; a warm pass is one 14ms git call
plus N small file reads. The lease generously exceeds the cold case.

`MaxBackoff` is zero, matching `backupjob`'s rationale: failures here are cheap
and idempotent, and backing off would leave the cache stale exactly when the
probe path is known to be sick. The runner's recorded fault is the alarm.

**`internal/reapjob`** — name `worktree-reap`. `Interval: 1h`,
`LeaseTTL: 15m`. Enumerates projects whose tracking is not off
(`monitor.GetTrackingMode(id) != "off"`) and calls the existing
`ReapWorktreesForProject` for each. `maybeReapWorktree` is unchanged except that
condition 4 reads the cache instead of running `reapNothingToLand` — and reads
it in COMPUTE-ON-MISS mode, because the reaper must never act on a guess.
Conditions 5 (`git status --porcelain`) and 3/5 (`WorktreeInUse`) stay live and
unchanged: a destructive decision re-verifies the filesystem itself.

This closes the leak the hotfix accepted. The reaper's condition 4 becomes the
exact content answer again, so a worktree whose work landed under rewritten SHAs
with no `task_landings` row is finally reclaimable — and ◆, `task unsettled` and
the reaper agree about "landed" again, which the hotfix broke on purpose.

## Who computes and who does not

**Never computes — cache-only:**
`monitor.AnnotateSessionStatusUnsettled` (the ◆ column in `session status` and
`session monitor`). A missing or invalid entry yields "not yet computed", never
a fabricated verdict. This is the change that removes the continuous range-diff
load: **measured 584ms per row for e-1077, gone from every tick of every pane.**

**Computes on a miss, and writes what it computed:**
- `session-query worktree-unsettled` (the Go entry point Python's `task
  unsettled` shells to) — a direct question deserves a real answer.
- `internal/reapjob` — it is the writer; a guess is not acceptable before a
  delete.
- `internal/unlandedjob` — likewise.

**Stays live everywhere, never cached:** `git status --porcelain`. Filesystem
state changes without any ref moving, so it has no honest cache key. Measured
15-27ms per worktree; a pane renders a handful of rows (this session's view
renders 2), so the live cost is tens of milliseconds per tick — three orders of
magnitude below the range-diff it replaces.

## The fourth marker state

`unsettledMark` currently has three states: `◆` unsettled, `⊙` no work product,
space settled. Cache-only reading introduces a fourth, transient state — "not
computed yet" — and collapsing it into either `◆` or space would be a lie the
column already refuses to tell.

New glyph: **`·` (U+00B7 MIDDLE DOT)**, width 1, meaning "not yet determined".
Within this column the distinction against `⊙` is ring versus no ring and
against `◆` is dot versus diamond — the same silhouette discipline E-2107 used.
Its faintness reads as absence of information rather than as a state, which is
what it is. It is visible only until the job's next pass, and the monitor tick
is what fires the job, so the window is one interval.

`buildLegend` documents it on any rendered row that bears it, like the other two.
Like `⊙`, it must not veto `dim`.

## Code changes

**`internal/monitor/unlanded_cache.go`** (new). The cache: entry type, path
resolution via `--git-common-dir`, `git worktree list --porcelain` parsing, the
watermark protocol, atomic write, prune, and the two read modes
(`CachedUnlanded` / `ComputeUnlandedAndCache`).

**`internal/monitor/worktree_unsettled.go`**. `worktreeUnsettledAt` gains a mode
parameter. `WorktreeUnsettledAt` (the ◆ path) becomes cache-only;
`WorktreeUnsettledDetailAt` (the on-demand path) computes on a miss.
`UnsettledDetail` gains `UnlandedKnown bool` and an accessor, distinct from the
existing `IsUndetermined()` — "not computed yet" is not "the probe failed".

**`internal/monitor/worktree_unlanded.go`**. `unlandedCommits` is unchanged; it
is now called only by the two computing paths.

**`internal/monitor/default_branch.go`**. Key `defaultBranchCache` on the git
COMMON dir rather than the worktree dir, so 135 worktrees share one memo within
a process instead of 135. Readers on the cache-only path get the base name from
`watermark.json` and do not resolve it at all — which removes the resolver from
the display path entirely, the ~60% the analysis measured.

**`internal/monitor/reap_worktrees.go`**. `maybeReapWorktree` condition 4 calls
the compute-on-miss cache read instead of `reapNothingToLand`; delete
`reapNothingToLand` and `landedSHAs` if nothing else uses them.
`AnnotateSessionStatusUnsettled` switches to the cache-only read.

**`internal/monitor/session_status.go`**. `SessionStatusRow` gains
`UnsettledKnown bool`.

**`internal/sessionstatuscmd/session_status.go`**. `unsettledMark` gains the `·`
case; `buildLegend` learns it; `colorize` excludes it from vetoing dim.

**`internal/sessionstatuscmd/json.go`**. Add `"unsettled_known": bool`.
`"unsettled"` stays a bool (false when unknown) so existing consumers do not
break.

**`internal/sessionquerycmd/session_query.go`**. `newWorktreeUnsettledJSON`
carries the new field through to Python.

**`src/endless/task_cmd.py`**. `_unsettled_probe`'s no-worktree literal gains
`"unlanded_known": True`; `unsettled_item` renders "not yet computed" when it is
false. No SQLite added — this file already stays clear of it.

**`internal/hookcmd/claude.go`**. Remove all five `ReapWorktreesForProject`
calls (SessionStart, PreToolUse, PostToolUse, Stop, SessionEnd). Nothing
replaces them: the job runs on the existing `liveview` trigger, which already
fires `jobs.RunDue` on each monitor refresh behind a single-in-flight guard and
a database lease.

**`cmd/endless-go`**. Blank-import the two new job packages so their `init()`
registration runs, matching how the existing three are wired.

## Consequences accepted

- **No monitor running anywhere means nothing is reaped.** Reaping is a TTL-gated
  cleanup with a 14-day default; a machine with no monitor open for a while
  accumulates directories and reclaims them on the next monitor tick. On this
  project, jobs are suppressed inside self-dev worktrees, so it is the
  main-checkout monitor that drives both jobs — unchanged from how the existing
  three already behave. On a stranger's project `InSelfDevWorktree` is false and
  any monitor drives them.
- **A fresh clone shows `·` until the job's first pass.** One interval.
- **E-2113 still matters.** The job runs on a goroutine inside the monitor
  process, so Ctrl-C in a pane still kills in-flight git children and still
  records ERR-0010 against an innocent task. This change shrinks the window
  enormously — the probe is no longer running continuously — but does not close
  it. E-2113 is already filed and is not folded in.

## Not in scope

- **The shared per-repo patch-id index.** Filed separately as a `maybe` task. It
  would cut a cold miss from ~584ms to ~100ms, but every miss is now paid by a
  background job off any critical path, and a settled verdict survives base
  movement, so cold-miss storms are small. Measure before building it.
- **Reliable landing recording.** A fourth symptom, not this root cause. Worth
  doing for the ledger's own sake; not required to make this correct.
- **Rebasing worktrees onto the base to remove drift.** Reduces the cost of a
  miss by removing its input, but it is a separate mechanism with its own
  conflict and live-session hazards.

  (settled entry survives, unsettled entry invalidates), amend base (full
  flush), amend the branch (that entry only), change the configured base name

- A test asserting the cache-only read NEVER shells `git range-diff`, using the
