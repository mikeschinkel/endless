# Plan — E-1605: testscript/txtar + pytest forms + first dogfood suites

Deliver the two runner forms the verify system still lacks, then prove the whole
E-1603/E-1604 stack with two real `.endless/tasks/<id>/` suites that jointly
exercise gotest + txtar + pytest + raw-command.

## 1. testscript / `.txtar` form (Go CLI/e2e)

- Import `github.com/rogpeppe/go-internal` as a pinned go.mod dependency (module
  mode — locked in go.sum, not copied into a `vendor/` tree); `go mod tidy`.
- Convention: a `.txtar` suite is driven by a small Go test harness — a
  `TestScripts(t)` func calling `testscript.Run(t, testscript.Params{Dir: …})`
  — so it runs under plain `go test` (bare-clone safe) and is captured as a
  `gotest` check through the existing `-json` path. No new runner or format.
- The harness builds/locates the binary the scripts exercise — the
  system-under-test — and registers it as a script command. In these dogfood
  suites the SUT is Endless, so the harness builds `endless-go` from the repo; a
  downstream project's harness builds its own CLI instead. This adds no tool
  beyond the Go toolchain the project already has (vs. a standalone `testscript`
  binary, an extra install). Document where `.txtar` files live and how the
  harness builds/finds the SUT binary.

## 2. pytest form

- Add `pytest-json-report` as a dev dependency in `pyproject.toml` (the plugin
  E-1604's `pytest-json` normalizer parses); sync the env.
- Convention: a `pytest` first-class check emits to the json-report file the
  runner supplies (E-1603 already wires `--json-report --json-report-file`),
  normalized via E-1604. Confirm the plugin is discoverable under the runner's
  isolated env.

## 3. First reference suites (under each SUT's own id)

### `.endless/tasks/E-1758/verify.toml` — worktree-check exemplar (txtar + gotest)
- `gotest` check over the `internal/monitor` worktree-anomaly core (E-1758's unit tests).
- `testscript`/`.txtar` check: a script that builds a throwaway git repo, runs
  `endless-go … worktree check`, and asserts the anomaly output — the CLI/e2e showcase.

### `.endless/tasks/E-1603/verify.toml` — verify-runner exemplar (gotest + pytest + raw)
- `gotest` checks over `internal/verify` and `internal/verifycmd`.
- `pytest` check over the Python `task verify` wrapper (a dedicated test module or
  a scoped subset of `tests/test_cli.py`) — the pytest showcase.
- raw-command check driving `endless-go verify` against an inline fixture suite
  (the end-to-end assertions the interim `tests/tasks/e-1603-verify.sh` makes).

Both are multi-`[[check]]` manifests whose checks normalize and merge to one CTRF
report — the first real proof of discovery → isolation → capture → normalize →
merge with real runners.

## Scope boundary vs E-1623

E-1603 and E-1758 already carry interim `tests/tasks/e-16{03,58}-verify.sh` bash
scripts. This task converts those two into real `.endless/tasks/<id>/` suites as
the reference exemplars; E-1623 retrofits the remaining ~16 against this pattern.
Do not retrofit the other scripts here.
