# Plan

Three landable increments. Each leaves the tree green and shippable; do not
start the next until the previous has landed.

## Increment 1 — the tables, written but not yet authoritative

New schema change file `internal/schema/changes/e-2063-session-instances.sql`,
mirrored into `internal/schema/schema.sql`.

```sql
CREATE TABLE IF NOT EXISTS session_instances (
    id            INTEGER PRIMARY KEY,
    session_id    INTEGER NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    harness       TEXT    NOT NULL,
    first_seen_at TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%S','now')),
    last_event_at TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%S','now')),
    ended_at      TEXT,
    recap         TEXT,
    recap_through TEXT,
    UNIQUE (id, harness)
);

CREATE TABLE IF NOT EXISTS claude_cli_sessions (
    instance_id INTEGER PRIMARY KEY,
    harness     TEXT NOT NULL CHECK (harness = 'claude_cli'),
    uuid        TEXT NOT NULL UNIQUE,
    FOREIGN KEY (instance_id, harness)
        REFERENCES session_instances (id, harness)
);

CREATE INDEX IF NOT EXISTS session_instances_by_session
    ON session_instances (session_id, first_seen_at);
```

NO `UNIQUE (session_id) WHERE ended_at IS NULL`. `ended_at` is display-only —
see the analysis; adding that index re-opens a settled decision.

Backfill in the same change file: one instance per existing `sessions` row,
`first_seen_at` from `sessions.started_at`, `last_event_at` from
`sessions.last_activity`, `harness` from `sessions.platform`, `ended_at` set
when `state='ended'`, and a `claude_cli_sessions` row carrying
`sessions.session_id` where that is non-empty and `platform='claude'`.

Nothing reads the new tables yet. Land here.

## Increment 2 — resolution moves to the instance

`sessions.session_id` stays in place and keeps being written, so this increment
is reversible; it stops being the resolution key, not the stored value.

- `monitor.GetActiveSession(uuid)` resolves uuid -> `claude_cli_sessions` ->
  `session_instances` -> `sessions`, returning the Endless session.
- `monitor.TouchSession` upserts the INSTANCE (bumping `last_event_at`, clearing
  a stale `ended_at`), and upserts the `sessions` row only when no instance
  matches the uuid.
- SessionStart: when the window/task already has a session and the uuid is new,
  append an instance rather than inserting a `sessions` row. `payload.Source`
  (`startup`/`resume`/`clear`/`compact`) is currently read nowhere; read it here
  and treat anything other than `startup` as continuation.
- Close the prior instance (`ended_at`) when a clear appends a new one.
- `session_messages.session_id` FKs `sessions(session_id)` — the uuid, not the
  id. Re-point it at `session_instances.id` so a clear gives later transcript
  rows a new parent and no prior row is rewritten.
- Move `platform` off `sessions`; `session_instances.harness` is the single
  discriminator.

## The governing rule

**Any field that is a fact about the unique harness conversation moves to
`session_instances`. Anything that is a fact about the WORK stays on
`sessions`.** Applied to rows as well as columns, that is the whole migration —
and it is why keeping the FIRST `sessions.id` of a set loses nothing: once the
conversation-specific columns have moved, the surviving row holds only facts
that were never conversation-specific to begin with.

Columns that MOVE to the instance:

| column              | becomes                              |
|---------------------|--------------------------------------|
| `session_id` (uuid) | `claude_cli_sessions.uuid`           |
| `platform`          | `session_instances.harness`          |
| `started_at`        | `session_instances.first_seen_at`    |
| `last_activity`     | `session_instances.last_event_at`    |
| `state`             | per-conversation                     |
| `process_id`        | the process running THIS conversation|
| `transcript_offset` | how far THIS transcript is parsed    |
| `summary`           | per-conversation                     |
| `last_user_prompt`  | per-turn, so per-conversation        |
| `report_bounces`    | per-turn                             |
| `report_exempt`     | per-turn                             |
| `report_runs`       | per-turn                             |

Columns that STAY on `sessions`: `id`, `project_id`, `task_id`, `epic_id`,
`hidden`. These describe the work and its durable identity, and must survive a
clear.

Four columns are NOT classified here because they will not exist: `summary`,
`short_id`, `kind_id` and `plan_file_path` are removed by E-2074, which blocks
this task. `kind_id` takes the `session_kinds` table and its Go enum with it.
The instance gets `recap` / `recap_through`; `summary` is not carried over.

The same rule decides the referencing tables. Per-conversation rows follow their
conversation to its instance: `session_messages` (transcripts), `session_gates`
(relay checkpoints and the minimizer corpus triples — both per-turn),
`report_labels`, `session_navigations`. Per-session rows stay pointed at the
surviving `sessions.id`: `session_tasks`, `decisions.origin_session_id`,
`task_landings`, `project_next_events`.

Getting the per-conversation direction wrong is the failure that matters:
re-pointing those rows at the surviving session would flatten every prior
conversation into one and destroy exactly the history this redesign exists to
preserve.

## Increment 3 — the collapse, and the CLI

- Re-parent the multiple `sessions` rows per task that exist today (E-1307 has
  7; 1362 and 1322 have 6). NOTHING IS DISCARDED: the earliest row by
  `started_at` remains the session, and every other row BECOMES AN INSTANCE of
  it, carrying its own uuid, timestamps and `ended_at`. Seven conversations stay
  seven conversations; they stop being seven sessions. Re-point the referencing
  tables per the split above — per-conversation rows follow their conversation
  to its instance, per-session rows follow the survivor.
- `resume` refuses when a session has 2+ instances with `ended_at IS NULL`:
  print them ordered by `first_seen_at` ASC with ordinal, `first_seen_at`,
  `last_event_at`, message count and recap, and exit non-zero. Never close one
  automatically. `--instance <ordinal|uuid>` selects.
- `resume` and `goto --resume` share ONE resolver.
- Delete `spawn --new-session`; under one-session-per-task it cannot mean what
  it says. OPEN, and NOT yet decided by the requester: whether its one
  legitimate residue — "do not inject the prior conversation's context into the
  handoff" — is still wanted at all, and if so under what name. Do not invent a
  flag for it without asking.
- Split `spawn --reopen` into `reopen` (task-status verb) and `resume` (session
  verb; restores the worktree, navigates when a live owner exists).

# Verification

`tests/tasks/e-2063-verify.sh`, fail-fast on units then end-to-end through the
real hook against the sandbox DB (drive it with an explicit `--config-dir`, per
`tests/tasks/e-1953-verify.sh` — without that flag the hook's PinMainDB sends
writes to the REAL ledger).

1. A clear appends: feed SessionStart with a NEW uuid and `source=clear` for a
   window whose session exists; assert exactly one `sessions` row for the task
   before and after, and one more `session_instances` row after.
2. Resume does not append: same, `source=resume` with the existing uuid; assert
   the instance count is unchanged.
3. The prior instance is closed on a clear; the surviving one has
   `ended_at IS NULL`.
4. A stale `ended_at` blocks nothing: leave two instances open, insert a third,
   assert it succeeds. This is the regression guard on the rejected index.
5. `resume` with 2+ open instances exits non-zero, lists them ordered by
   `first_seen_at` ASC, and closes nothing — assert `ended_at` values are
   identical before and after.
6. `--instance` selects by both ordinal and uuid.
7. A `claude_cli_sessions` row cannot attach to a non-`claude_cli` instance —
   assert the composite FK rejects it.
8. Migration preserves history, asserted as a conservation law rather than a
   row count: for each task, `COUNT(session_instances)` after == `COUNT(sessions)`
   before, and every pre-migration uuid is still reachable. Then per-conversation
   rows: no `session_gates` / `session_messages` / `report_labels` row may end up
   parented to an instance whose uuid differs from the session uuid it had
   before. That is the assertion that catches a flattening migration; a bare
   pre/post row count would not.
9. `sessions.platform` is gone and nothing references it.

Not verifiable by test: whether one open instance per session is actually
maintained in the field. Nothing enforces it at the storage layer by design —
that is E-1983's invariant gate plus write-once `task_id`.
