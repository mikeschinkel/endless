# Auto-set a done task to `revisit` when its plan text is edited — PLAN

## Context
Editing the plan (`tasks.text`) of a task that is already in a done state adds
unshipped scope, so the done-status becomes a lie AND the task stays hidden from
session monitor. Today the fix is manual (an agent must remember to run
`task update <id> --status revisit`). In a product used across ~40 projects, that
depends on every agent/user remembering — the wrong layer. Make the CLI do it.

Surfaced when E-1744 (status `assumed`) gained built-in allowed-paths scope and had
to be hand-flipped to `revisit`.

## Behavior
In `update_plan` (`src/endless/task_cmd.py`): when a `task update` changes
`tasks.text` AND the task's current status is a *successfully-done* terminal state,
auto-transition status → `revisit` and ANNOUNCE it (e.g. "E-NNN was assumed; plan
text changed → status set to revisit").

## Design decisions (confirm with Mike)
1. **Which statuses trigger it** — recommend the *completed-successfully* set:
   `assumed`, `confirmed`, `completed`. EXCLUDE the *abandoned* set (`obsolete`,
   `declined`): editing an obsolete task's plan is usually doc cleanup, not a
   revival, and auto-reviving would be surprising. Confirm.
2. **Trigger field** — `tasks.text` (the plan) ONLY. Editing `--outcome` /
   `--analysis` / `--description` on a done task is normal (recording results) and
   must NOT reopen it.
3. **Only on real change** — diff existing vs incoming text; an identical re-write
   is a no-op (no flip).
4. **Escape hatch** — a `--keep-status` flag to suppress the auto-flip for a pure
   typo/formatting edit. Recommend including it. Confirm the name.
5. **Epics are special** — flipping an EPIC to `revisit` triggers the E-1542
   pause-on-revisit gate for every in-flight descendant session. That may be
   intended (the epic's strategy changed) or too blunt for a plan tweak. Decide
   whether epics auto-flip like leaves, or are excluded / warned instead.

## On completion
Prune `feedback_revisit_resurfaces_in_monitor.md` and its `MEMORY.md` line — the
behavior is now automatic, so the memory (interim reinforcement) is obsolete.

## Deliverable — verify script
Generate `tests/tasks/e-<id>-verify.sh` (shape per `tests/tasks/e-1577-verify.sh`,
sandbox DB): editing `--text` on an `assumed` task flips it to `revisit` and
announces; identical-text re-write does NOT flip; `--outcome` edit on a done task
does NOT flip; `--keep-status` suppresses; a non-done task (e.g. `underway`) is
unaffected. On completion set `unverified` and hand off exactly:
`esu && ./tests/tasks/e-<id>-verify.sh`.
