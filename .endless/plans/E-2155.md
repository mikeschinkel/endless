# Plan — every refusal and warning says whether the agent may continue alone

## The rule (Mike, 2026-09-17)

**An agent reports a refusal or warning to the user ONLY when it cannot continue
without input from the user.** Everything else is NO-REPORT.

In particular, a message of the shape "you must do X instead of Y" is NO-REPORT:
the agent calls the command again doing X. Nothing about that needs the user, and
relaying it spends the attention the guardrail exists to save.

This replaces the earlier test in this task's analysis ("after the agent complies,
does the user's outcome differ?"). That test asked about outcomes; this one asks
the only question that decides whether a human is needed, and it is stricter.

Consequence: NO-REPORT is the overwhelming majority. REPORT is the exception, and
every REPORT site should be able to name the decision only the user can make.

Examples:

| Message | Class | Why |
|---|---|---|
| analysis contains an absolute path | NO-REPORT | rewrite it project-relative and retry |
| description over 1024 chars | NO-REPORT | move the long form to --analysis and retry |
| title verb not allowed for this task type | NO-REPORT | pick an allowed verb and retry |
| refusing to remove a worktree | REPORT | removal is the user's act, not the agent's |
| status transition not reachable | NO-REPORT when a legal path exists, else REPORT | classify per site |

## Explicit, never defaulted

Every refusal and warning site carries an explicit classification. There is no
default. A site without one fails the build.

That is the point, not a convenience: a default in either direction is a
classification nobody made. Default-to-report reproduces today's noise;
default-to-silent eventually swallows a genuine blocker. Refusing to build forces
the decision at the moment someone writes the message, when the answer is obvious.

## Scope

**Refusals and warnings, in Python AND Go, fully.**

- Python: `click.ClickException`, `click.UsageError`, and warnings echoed with
  `err=True`. Counted 2026-09-15: 423 raises, 91 warning echoes.
- Go: every user-facing stderr refusal or warning. Counted: 295 stderr writes and
  177 error sentinels (overlapping, and not all user-facing — the inventory decides
  which are).

**Why Go fully, not just where an agent reads it directly:** E-1063 migrates the
whole CLI surface to Go, with one binary named `endless` as the end state — and it
does not start until after this task lands (Mike, 2026-09-17). So the order is:
classify, then port.

That makes the inventory an INPUT to the port rather than throwaway work. Each
Python refusal's class is carried forward when E-1063 moves it to Go. And it is why
the Go mechanism and the build-refusing test should exist BEFORE the port begins:
every refusal ported into Go is then born classified, and the enforcement catches
any the port misses, instead of the port landing unclassified refusals that need a
second pass.

Separately from the port, Go already has user-facing refusals of its own — hooks,
event, session-query — which need classifying regardless.

## When the directive fires

The NO-REPORT directive is emitted when ANY of these holds, and never otherwise:

1. **An agent is detected from the environment.** Python `agent_env.present()`, Go
   `internal/agentenv.Present()` — the same rule on both sides, keyed on the
   environment the harness sets (`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`,
   `AI_AGENT`). This is the path an agent takes without doing anything, and Endless
   already uses it in many places.
2. **`--agent` was passed.** The token-efficient output flag that superseded `--llm`
   (which is retired, and survives only as a pointer to `--agent`).
3. **`--agent-view` was passed** — a human asking to see what an agent sees.

A human at a terminal with none of these sees today's message unchanged.

## The mechanism, per side

**Python — the seam exists, with one gap.** `agent_help.agent_facing()` is the
single place that answers "is an agent reading this?", and `agent_help.agent_error()`
(E-2097) already shapes a refusal for that audience. Two problems:

- `agent_facing()` is `agent_env.present() or _AGENT_VIEW` — it honours the
  environment and `--agent-view` but NOT `--agent`. Trigger 2 above has to be added
  there, in the one place, not at each call site.
- `agent_error()` has exactly ONE caller against 423 raise sites.

**Go — detection exists, the helper does not.** `internal/agentenv.Present()` already
answers the audience question (4 callers). What Go lacks is the equivalent of
`agent_error()`: nothing shapes a refusal or warning for an agent. The follow-on
builds that helper on top of `agentenv.Present()` plus Go's reading of `--agent`, so
both sides answer the audience question the same way.

## What this research task produces

It changes no code.

1. **The inventory** — every user-facing refusal and warning on both sides, each
   with its class (REPORT / NO-REPORT) and, for every REPORT, the decision only the
   user can make. A site whose class depends on runtime state (the status
   transition above) is marked per-site with the condition, not averaged.
2. **The enforcement design** — how the build refuses an unclassified site on each
   side. Likely a test that walks the raise and stderr sites and requires each to
   go through the classifying helper; the research names the exact shape.
3. **Filed todo task(s)** to apply it — split by side if that is the honest shape,
   noting in each that the Go mechanism should precede E-1063's port.
4. **An outcome** stating the counts, the REPORT list in full (it should be short),
   and anything that did not fit the rule.
