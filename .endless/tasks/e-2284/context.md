Opt-in settings such as main_sync, auto_spawn, prime and the minimizer are off by default and nothing tells users they exist. The doctor design makes the doctor metadata part of declaring a setting, so a setting cannot exist without its rationale and check. Tri-state (unset/on/off) lets doctor suggest only unset settings and treat an explicit off as a decline, stored at the setting's own scope: committed for project settings, machine config for machine settings. Where settings are declared today is unknown, so the work starts by finding every existing setting and moving it into the registry. Registration in init() must not be able to fail; validation belongs in Initialize() error so the CLI exits gracefully.
