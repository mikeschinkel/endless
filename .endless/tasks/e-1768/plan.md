`endless session status` shows a false-positive anomaly line under the focal task. For the session's own active (focal) task row, the ◆ marker expands to "◆ uncommitted: N uncommitted/untracked user files (…)" listing the files being edited FOR that task — the normal work-in-progress state of the task you're actively working on, not an anomaly.

Root cause: E-1758 (commit b9ca710c) unified two surfaces onto one monitor.WorktreeAnomalies set. `endless worktree check` runs at HANDOFF, where a clean tree is expected, so uncommitted user files ARE a genuine anomaly (correct — leave unchanged). `endless session status` renders CONTINUOUSLY, including on the focal task you are mid-implementation on, where uncommitted files are EXPECTED — so the AnomalyUncommitted kind is a false positive there. The other three kinds (AnomalyDetachedHead, AnomalyBranchMismatch, AnomalyPrunable) are genuine even mid-work and must still surface.

Fix: in internal/sessionstatuscmd/session_status.go, the focal-row expansion loop (guarded by r.IsFocal, iterating monitor.WorktreeAnomalies(r.ProjectID, r.ID)) must skip anomalies of kind monitor.AnomalyUncommitted while still printing the other kinds. Do NOT touch the shared WorktreeAnomalies core or the `worktree check` surface — only the session-status focal render. The ◆ glyph on the focal row itself stays (it correctly means dirty-or-unlanded per E-1701); only the expanded "uncommitted" detail line is suppressed.

Tests: add a Go test in internal/sessionstatuscmd (or extend the existing session-status render test) asserting the focal expansion omits an uncommitted-only anomaly but still emits detached-head / branch-mismatch / prunable. Keep the existing worktree_anomalies tests green (worktree check behavior is unchanged).
