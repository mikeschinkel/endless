E-2335 code review: task spawn claims the task (underway, worktree created) before Claude starts, and the session-to-task binding is written only by the SessionStart hook. Nothing waits for or checks that SessionStart. If hooks never fire, the task sits underway with no claimant and a second spawn is allowed. autospawnjob's outstandingAutoSpawned counts only tasks joined to sessions with auto_spawned=1, so hookless auto-spawns never fill the cap and the job keeps claiming one more task each interval.
