Declined: it would put machine-local state into a project-scoped shared record. The proposal was worktree.created and worktree.destroyed events, a session_worktrees index, and a listing verb. Worktrees are user-machine artifacts, not project facts: their paths exist on one developer's disk. The db-ledger is project-scoped and committed, and E-1829's multi-developer milestone depends on each developer rebuilding their projection from that shared ledger — so emitting worktree paths as ledger events would ship one machine's filesystem layout to everyone rebuilding from it. E-1883 is already open on the tension between a project-scoped ledger and a machine-global DB; this would deepen it. 'endless worktree list' already answers the local question locally.
