Liveness reads 'unknown' whenever it could not reach a session's tmux server, and nothing distinguishes 'unreachable right now' from 'gone for good'. A session whose server died (a tmux restart) therefore reads unknown forever and counts as live everywhere that treats unknown as live. Measured 2026-10-11: session 1113 is bound to server 79dabb93…, which matches no server now running, and about 15 non-ended sessions are bound to vanished servers. E-2293 worked around one symptom (stewardship now requires 'live'); the claim guard and in-flight markers still treat these ghosts as live, so a claim held by one is refused permanently until someone ends it by hand. Observation already enumerates every socket in the tmux socket directory, so a recorded server uuid absent from all of them is very likely gone. Risk is high: the 2026-08-05 incident came from condemning sessions without evidence, and edge cases include a non-default TMUX_TMPDIR, other users' servers, and a socket that is momentarily unresponsive. Once this lands, revisit whether E-2293's 'live'-only stewardship rule is still needed.
