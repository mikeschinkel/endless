Two options considered. (a) auto-reap the ghost owner inside the guard; (b) add a manual clear command and point the error message at it. Chose (a): monitor.ReapDeadTmuxPanes already exists and is explicitly opportunistic, so the only gap is that the spawn/claim guard never consults it.
