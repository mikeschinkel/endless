Add a `gomod` subcommand group to endless-go (cmd/endless-go dispatch, listed in its usage) with three commands. Logic lives in a new library package internal/gomod; the CLI in internal/gomodcmd. No `endless` (Python) wrapper: justfiles call endless-go directly.

`endless-go gomod next-version [DIR] [--json]` — DIR defaults to the current directory and must hold a go.mod. Find the module's previous tag by directory prefix (<dir>/vX.Y.Z for a nested module, vX.Y.Z at the repo root, highest by semver). Extract the repo at that tag to a temp directory (git archive), load the old and new module with GOWORK=off and the caller's environment (GOEXPERIMENT included), and diff them with golang.org/x/exp/apidiff in module mode (as `apidiff -m`). Print each incompatible and compatible change, then the proposal: any incompatible change gives a minor bump on v0 or a major bump on v1+, else a patch. No previous tag proposes v0.1.0. Warn, without changing the proposal, when a require's version moves across a 0.X boundary between the tag and HEAD.

`endless-go gomod floors MODULE [--root DIR] [--json]` — walk every go.mod under DIR (default: current directory), skipping .endless and vendor directories. For each require of MODULE or a module under MODULE's path, print the requiring module, its go.mod path, the required version, and its state: published (the Go proxy lists it, via `go list -m -versions` or the proxy protocol through golang.org/x/mod), tagged but not resolvable (git ls-remote on the module's repo finds the tag), never tagged, or replaced locally (the requiring go.mod replaces it).

`endless-go gomod release-check [DIR] --version vX.Y.Z [--no-test] [--json]` — refuse, listing every failure: a dirty worktree; HEAD not equal to origin's default branch (read with git ls-remote, no fetch); a module path that does not match the repo and directory; any replace directive; any require not published; `go mod tidy -diff` reporting changes with GOWORK=off; the tag (<dir>/vX.Y.Z or vX.Y.Z) already existing locally or on origin; a version not above the previous tag. Then, unless --no-test, run `go test ./...` with GOWORK=off in the module and in DIR/test when that is a module. Print the next-version proposal alongside, and warn when --version differs from it.

All three exit non-zero on a refusal and keep stdout for results. Tests build temporary git repos with tags and serve published versions from a file-based GOPROXY, so no test touches the network.

Document the group in the endless-go usage text and in Endless's guide reference.
