One Endless database holds many projects, so every recorded fault from every project lands in one undifferentiated table, and the detail log compounds it: monitor.ConfigDir() (internal/monitor/db.go) resolves to the single shared ~/.config/endless for any caller pinning --db main. Consequences: `endless errors show` cannot filter by project, the session-status error badge cannot be project-scoped, the unique index on (source, code, fingerprint) can collide across unrelated projects, and any new fault producer must smuggle attribution through Source or Fields. This reads as an oversight in E-698 rather than a deliberate choice.
