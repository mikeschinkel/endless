Seen 2026-10-24 landing a go-dt task: after the fast-forward, worktree land commits task.landed as a separate 'Endless: record ledger entry' commit touching only .endless/db-ledger/, which becomes main's tip. GitHub Actions names a push run after its head commit, so the go-dt Test run was labeled 'Endless: record ledger entry' instead of the task's last commit ('Add verify suite'). Every Endless-managed repo with CI gets this on every land; Mike called it a hellish UX. Options weighed: (1) push in two steps, main up to the task tip first and the ledger commit after with [skip ci], which fixes every repo without touching workflows; (2) workflow run-name or a paths-ignore on .endless/**, which doesn't work, because run-name can only read the head commit and a push holding both code and the ledger commit still runs under the ledger label; (3) write the ledger entry onto the task branch before the fast-forward, which records the land before it happens. The approach is open; (1) leads.
