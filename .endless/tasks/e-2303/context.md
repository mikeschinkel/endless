Endless config is one struct, EndlessConfig in internal/config, that every reader consumes directly, so nothing guarantees a value was validated. Mike's pattern from gomion keeps a file-shaped struct (gommod/gomcfg) and a separate runtime config (gommod/gompkg/config.go) built by Parse() functions (gommod/parse_config.go); once parsed, values can be trusted. The settings-registry work moves only the registered opt-in keys onto this split, tracked by an allowlist of keys not yet registered. This task finishes the rest and empties that allowlist. Representation must be consistent across keys: no bool-where-missing-means-something for some keys and three-state strings for others.

This task also renames "layered" to "overlayed" throughout internal/config (README, comments and identifiers), per decision ED-1620.
