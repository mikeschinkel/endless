Endless installs its hooks machine-wide in the user's Claude Code settings, so every session in every directory invokes endless-go on every hooked event — including projects that will never use Endless.

Folded in from E-2339 (block cloud sessions on Endless-managed repos). E-2335 probed two committed guards on real cloud sessions, each on UserPromptSubmit with onFailure block: a shim exiting 2 when CLAUDE_CODE_REMOTE=true, and a hook pointing at a binary present only on the user's machine. Both refused every prompt before the model ran. So Endless's own hook entry, committed in the project's settings with onFailure block, is by itself a cloud block; a shim adds only a clear message and a pass-through for collaborators' local sessions. Limits: a cloud session loads hooks only from the repo it started on, so one started elsewhere can clone and push without the guard (inbound-commit inspection is the backstop); multi-repo sessions reportedly skip repo hooks (not probed). PRODUCT: a committed guard affects every collaborator on the repo. Mike: cloud is blocked for now; future support is E-2344.
