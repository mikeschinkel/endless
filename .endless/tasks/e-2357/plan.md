Two user-visible changes in the session status graph, both in internal/sessionstatuscmd/graph.go.

**Your own task never leaves the graph.** graphSeeds today skips every row whose task has a landing record before it looks at whether the row is the session's own task, so your own task disappears the moment it lands. Reorder the switch: the own-task case comes first and always keeps the row; the landed check then applies only to other rows, as today. Mike's picture: the own task is the "You are here" pointer on a mall map, so the graph dims it but never removes it.

**One intensity rule for every id.** lineSegments today dims an id only when it has already been drawn on an earlier line (a `seen` map), with in-flight ids exempt; status is never consulted. Replace that with: an id draws dim when its task has landed or its status is terminal (taskrow.IsTerminal, the predicate rowIntensity already uses for the table), and bright otherwise. Drop the `seen` map entirely, so every copy of an id draws alike. In-flight ids keep drawing bright because they are neither landed nor terminal.

**Carry the landed flag to the renderer.** monitor.GraphNode has Status but not whether the task has landed. Add a Landed bool, filled in monitor.SessionGraphData from the same task_landings existence test SessionStatusRow.Landed uses, and emit it on jsonGraphNode as `landed`. The predecessor query already excludes terminal statuses, so the own task is the only node that can be terminal or landed when it reaches the renderer; the rule is still written for every id so it holds if that changes.

**Tests** in internal/sessionstatuscmd/graph_test.go, using the existing newGB builder: a landed own task stays in the graph and draws dim; a completed brainstorm own task (no landing record) draws dim; a ready own task draws bright; an id that appears on two lines draws the same on both. Remove TestGraph_RepeatsDimInFlightDoesNot, whose assertion the new rule contradicts; keep its in-flight-is-bright half inside the new repeated-id case. A graphSeeds test covers the landed own task being kept.

**Docs** The graphSeeds and lineSegments header comments and the "Which tasks appear" paragraph of docs/guide/sessions.md say: your own task always appears, bright while it needs work and dim once it has landed or reached a terminal status; every other appearance of an id draws the same as its first.
