Today Endless has no notion of releasing. A task whose plan ends in a tag (go-testutil's E-2674 needed v0.4.0 pushed so a go-cliutil task could require it) carries that as a post-land plan item, and the session hand-writes a one-off script for it: E-2674 got .endless/tasks/e-2674/release.sh, which runs gh with an emptied environment so gh uses its keychain credentials, computes x.+1.0 for a breaking change or x.x.+1 otherwise from the latest remote tag, writes an active-voice description with backticked code, dispatches the repo's release.yml and follows the run.

Mike asked (2026-11-26) for a quick-and-dirty version now: a 'project release' command that calls a release.sh script, plus handoff-doc and guide changes so projects that need releasing have it built into their workflow.
