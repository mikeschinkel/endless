Claude Code always pipes a JSON payload into its hooks, so an empty stdin with no event named is a hand run (both ERR-0017 faults seen were agents exploring the command: 2026-10-09 from e-2278, 2026-10-18 from e-2373). Requiring the event argument makes every other combination diagnosable: a payload with no argument is an entry written before this change, and a payload naming a different event is an entry wired wrong — both fixable by the user with `endless setup claude-hook`, so both are faults the user sees (Mike: a cause the user can recognize and fix should be a fault). An empty or invalid payload with the event named is either a wrapped entry, which setup reports, or Claude Code's bug; Endless cannot tell them apart, so ERR-0017's remedy checks the entry first and then points at Anthropic. A broken payload leaves sessions untracked and every PreToolUse gate inactive, which is why E-1661 grades it exit 2 (Stop and SubagentStop excepted, where exit 2 starts an uncapped loop of model turns); `hooks.dangerously_continue` is the user's explicit opt-out for the Claude-side causes only. Detecting a valid payload in a new format, which Endless would have to adapt to, is separate work.
