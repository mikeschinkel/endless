Claude Code always pipes a JSON payload into its hooks, so an empty stdin is either a hand run (both ERR-0017 faults seen were agents exploring the command: 2026-10-09 from e-2278, 2026-10-18 from e-2373) or a Claude Code bug. A Claude Code bug that empties payloads leaves the session untracked, which E-1661 says must reach the agent (exit 2) — except on Stop and SubagentStop, where exit 2 starts an uncapped loop of model turns. The event name arrives inside the payload, so an empty payload cannot be graded; naming the event on the command line restores that, and makes "no event named" mean a hand run, which gets usage instead of a fault. Checking the named event against the payload's also catches a settings entry wired to the wrong event. Existing installs get the argument through a setup repair, the same route E-1901's async-flag change and the missing-event repair took; until a machine re-runs setup, an empty payload there gets the hand-run answer, no worse than today.
