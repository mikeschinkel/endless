ED-1357 (accepted) says every hook error blocks. E-1661 already did the bulk of it: an error a handler returns to Run in internal/hookcmd exits 2 (hookExitCode in halt.go), except on Stop/SubagentStop, which exit 1 because exit 2 there starts another model turn and the loop guard (monitor.BumpReportBounce) lives in the database that may be what failed. The old analysis line "change main.go's os.Exit(1) to 2" is therefore done.

What remains, and the choices Mike made on 2026-10-15:

- Log-and-continue sites: places in a handler where an error is logged and the hook carries on as if it succeeded (find them with a search for log.Printf in internal/hookcmd). Mike chose to split them: a site whose failure leaves tracking, a worktree lock or a gate's state wrong returns its error; a site that only affects side work (the throttled DB backup, A/B sample rate and pick, report labels) stays non-blocking and records a fault. Blocking side work would refuse the prompt over something the current task does not need; converting async-event sites (SessionEnd, Notification) changes nothing because nobody reads their output.
- Stop/SubagentStop: Claude Code's Stop payload carries stop_hook_active, true when the turn is already continuing because of a Stop hook. That is a loop guard that needs no database. Mike chose: exit 2 once and exit 1 when stop_hook_active is true, provided a probe shows Stop's exit-2 stderr reaches the model (halt.go's comment says it goes to the person; Claude Code's docs say the model). Otherwise keep exit 1.
- Schema refusals (E-2020) exit 0 and record a fault. ED-1357 says they block, and Mike chose that: a schema mismatch means tracking is wrong, so a session must not continue.
- Hooks that cannot run (folded from E-2340): a missing, crashing or timed-out binary fails open unless the hook entry sets onFailure "block" (Claude Code 2.1.295+). It only has effect on PreToolUse and UserPromptSubmit among the probed events. Mike chose that setup refuses an older Claude Code rather than install fail-open hooks; nobody has a lasting reason to stay on an old version.
- Hook-fix opt-out: a session fixing the hook needs to get past the block. Mike rejected environment variables: they are inherited by everything a process starts, so a variable meant for one session can affect another, and one set at launch cannot help a session already running. He chose a command, endless hook bypass, with an optional session-ref argument or --all, an optional --for duration on both, a default duration for --all, and --clear. The bypass lives in a file in the user's Endless config directory, not the database (a broken database must not stop the hook reading it) and not the repo (nothing committed). The hook reads it on every call, so it reaches running sessions. Under a bypass, errors are non-blocking but gates still run, so a fix session still cannot edit main. Only a person may run it: an agent lifting its own block defeats ED-1357. It cannot cover a missing binary, since the binary reads the file; Claude Code's own disableAllHooks is the escape there.
