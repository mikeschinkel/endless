Found while working on E-2294. The test in internal/sessionquerycmd runs the endless-go binary with ensure-claude-id --process %9 and checks that the session row is bound to %9. It passes under just test-go when run from inside tmux, because the binary inherits the developer's tmux and can stamp a server identity. It fails under endless task verify, which isolates tmux (process = "", want '%9'). It also fails when run with TMUX unset and TMUX_TMPDIR pointed at an empty directory. So the test depends on the environment in two ways. First, any verify suite that runs ./internal/sessionquerycmd fails; E-2294's suite had to leave that package out. Second, when it does pass, it is running against the developer's real tmux server, which is the hazard monitor.SetTestTmuxServer exists to prevent. That helper cannot be used directly here because the test runs a compiled binary rather than calling the code in-process.
