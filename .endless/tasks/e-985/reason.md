Superseded by E-996, which landed the same fix on 2026-05-01 (b7f12cb). Both describe one problem: go.mod's relative replace directives resolve from the worktree instead of main, so a Go build inside a worktree fails. E-996 settled it with go.work, generated per worktree by the 'just go-work-init' recipe, which 'just install' runs as part of worktree setup — so it is wired automatically at creation, not applied by hand each time. Nothing has been absorbed quietly: the failure stopped occurring because the setup path fixes it before a build is ever attempted. What E-985 raised that E-996 did not close is the PRODUCT half — a user on another project with npm link, nvm, pip install -e or cargo patch has no equivalent — and that is E-1086's scope, already underway.
