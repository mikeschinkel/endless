**Two commit layers, one fix.** Endless commits its own files to main through two layers: Go's `events.commitPaths` (internal/events/commit.go: `CommitLedgerSegment`, `CommitDoc`, `CommitDocPaths`, `CommitVerifyReport`; reached from Python's doc_mirror through `endless-go event commit-doc`) and Python's `main_commit.commit_path`/`commit_paths` (src/endless/main_commit.py: lessons, matchers, register, verify_cmd, project_identity). Both commit onto whatever branch the main checkout has checked out. Python's `main_commit` moves onto the Go path, as doc_mirror already does, so the fix is made once in Go.

**Changes, not paths (Mike, Q3 = B).** The commit layer takes changes instead of paths a caller has already written: replace a file with this content (document mirrors, templates, verify reports, matchers, project identity) or append these lines to a file (ledger segments, LESSONS.md). Callers stop writing these files themselves.

- **Main checkout on its default branch:** the layer writes the change into the working tree and commits it as today, keeping the `ensureMainCheckout` refusal, the `index.lock` retry, GIT_DIR-family stripping and ledger-commit amending.
- **Main checkout on any other branch:** the layer applies the change to the default branch's copy of the file, building the commit with plumbing (`hash-object`, a temporary index, `write-tree`, `commit-tree` on the default branch's tip) and moving `refs/heads/<default>` with `update-ref` against the tip it read, retrying when another writer moved it first. It does not touch the main checkout's working tree or index, and it never amends.

The default branch is `monitor.DefaultBranch` (config `default_branch`, then origin/HEAD, `init.defaultBranch`, `main`/`master`), the same branch `worktree land` lands onto.

**Templates (Mike, Q1 = B).** `endless-go template render` run from a worktree materializes a missing template in the main checkout, through the commit layer above, and renders from the current checkout, falling back to the embedded template where the current checkout lacks the file. The main checkout comes from `mainCheckoutFromWorktree`, moved out of internal/sandboxcmd into a package both can import. `commitMaterialized` and templatecmd's own `runGit`/`isGitWorkTree` commit helpers are deleted in favour of the commit layer.

**Spawn renders the task's project.** `_render_handoff` in src/endless/task_cmd.py passes `--project <the spawned task's project>` to `template render`, so a spawn run from another project's worktree neither renders nor materializes that other project's templates.

**Tests.** Go tests in internal/events for both branches of the layer (on default branch; on another branch, with a replace and an append each), for the `update-ref` race retry, and for the main checkout's working tree and index being left untouched on another branch. A templatecmd test renders from a worktree whose project lacks the template and asserts no commit on the task branch and one on the default branch. A Python test that a spawn from project A's worktree for a project-B task materializes nothing in A.
