**Q1 — where a worktree render materializes (Mike: B).** Options were: main checkout for both render and materialize (a task branch's edited template would not render in its own worktree); materialize in main but render from the current checkout (chosen); never materialize from a worktree (projects that always spawn from worktrees might never get the file); materialize without committing (an untracked file in the main checkout, which blocks `just land`).

**Q2/Q3 — main checkout on another branch.** First framed as a template question with "skip", and as a consistency cost if only templates committed to the default branch. Mike: the other auto-commits have the same bug, so it is one cause and one task (ED-1550). For what a default-branch commit contains, options were: the working-tree file's content (corrupts an appended ledger, since the file on disk is the other branch's copy); callers describe a change applied to the default branch's copy (chosen); a separate Endless-owned checkout of the default branch (the main checkout's own branch moves under it and its working tree goes stale when it is on the default branch); skip and warn (leaves writes for someone's next `git commit -a` to put on the wrong branch).

**Why Python moves to the Go path.** Two commit layers would need the same plumbing twice; doc_mirror already reaches Go through `endless-go event commit-doc`, so there is precedent and one place to test.
