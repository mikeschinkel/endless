- **No existing path resumes a task-bearing session without a worktree.** Every route cds into `.endless/worktrees/e-N`. E-1918's plan explicitly rejected resuming into the project root. Mike reaffirmed on 2026-10-16 that the root must never be a resume target, because it breaks other sessions' ability to land.
- **Where the "landed" assumption comes from.** Both Python (`_resolve_resume`) and Go (`resumewindows.decide`) infer "landed" from "no worktree on disk" alone. `landed_sha` is consulted only later, as a base. So a bound-but-never-claimed task (possible since `task bind` and binding during planning) gets "dropped after landing", and then `--review` fails with "never landed… no base".
- **Why `--recreate` refuses when a branch exists.** `--reopen` already reuses a surviving `task/N` branch and leaves a never-landed, open task's status unchanged (`_REOPEN_TO_REVISIT` only flips done tasks). Keeping `--recreate` to the no-landing, no-branch case means the three flags never overlap, and `--recreate` can never stand in for a recovery that has real history to recover from.
- **Why it stays status-neutral.** Writing still needs `task claim`, and the claim's plan gate applies. Mike chose this on 2026-10-16. A claim could be added later if usage shows a need, though he expects the flag to be rare.
- **Why bulk resume never runs `--recreate`.** Recreating is a deliberate act: the session lands in a tree it never saw. So bulk resume only suggests the command.
