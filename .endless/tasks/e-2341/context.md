E-2335 probed Remote Control server mode (claude remote-control) with two sessions spawned from the iPad: every hook fired, but CLAUDE_CODE_ENTRYPOINT is sdk-cli with no CLAUDE_CODE_BRIDGE_SESSION_ID. agentenv classifies sdk-cli as Unknown, supportedAgent() is false for Unknown, so Endless's hook exits 0 and the CLI treats the agent as a human (agent-only refusals don't apply). Remote Control is a supported surface (Mike, 2026-10-14), and server mode is part of it. Interactive claude --remote-control sessions report cli and carry the bridge id after connect, so they are covered. Endless's own internal claude -p calls set ENDLESS_NO_HOOKS. Options include recognising sdk-cli as supported, distinguishing server-mode spawns from scripted claude -p, or refusing work from unmanaged harnesses in registered projects.
