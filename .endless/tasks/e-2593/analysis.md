Linux can make a fixture appear to BE the root without root privileges: a user namespace plus a mount namespace (`unshare --user --map-root-user --mount`), bind-mount the fixture and the binaries it needs, then chroot or pivot_root into it — the mechanism Docker uses, minus the image. bubblewrap (`bwrap`, used by Flatpak) wraps all of it in one command. Some distros restrict unprivileged user namespaces (Ubuntu 24.04 does, through AppArmor), so the runner must detect that and say so, not fail obscurely.

macOS has no equivalent: no mount namespaces; chroot needs root and a copy of dyld and its shared libraries; sandbox-exec can deny paths but not remap them, and is deprecated. Apple's container tool runs Linux containers in lightweight VMs, not macOS containers. So on macOS the portable route stays E-2592's --base-dir.
