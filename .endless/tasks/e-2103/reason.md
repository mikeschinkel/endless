Not worth a schema change. session_notices.task_id is NOT NULL, so decision notices need a column added and a constraint relaxed — not the trigger-only change it looked like. Decisions are moving back into tasks, at which point the task notify path covers this for free; paying a migration for a surface with a known expiry date is the wrong trade. The gap is real and stays unaddressed deliberately: a session will not learn that a decision it filed was accepted or rejected.
