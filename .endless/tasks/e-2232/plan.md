Main's side gets the same treatment, so main's replayed copies are not "landed" either.
2. A real collision (both sides' own commits add migrations) refuses as before, rename steps included; it runs first, since its step 1 is already `git rebase main`.
3. Otherwise, when the branch holds commits patch-equivalent to commits on main AND those copies add files under the migration dirs, refuse with a distinct verdict (source `base_rewritten`): main was rewritten since the branch forked; run `git rebase main` in place and land again. No rename steps. Copies that add no migration are allowed: they cannot mislead about numbering, and land's own rebase drops them (e.g. a commit cherry-picked from the branch onto main). This narrows the original plan, which refused on any patch-equivalent commit; agreed with Mike in session.
4. Python classifier (src/endless/worktree_cmd.py) treats `base_rewritten` as no_report, like a migration collision.
