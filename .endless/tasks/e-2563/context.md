Go looks for go.work by walking up from the current directory. Task worktrees live inside their main checkout, so a go.work there is found from the worktree, and Go then refuses to build because the worktree's modules are not listed. This breaks go-cliutil and go-cfgstore worktrees today. The nearest go.work wins, so one in the worktree shields it; listing only its own modules keeps its builds on published versions. Nested test/ and examples/ modules must be listed too.
