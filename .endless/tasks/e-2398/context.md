Inside a worktree, endless-go loads its CLI config layer from the worktree sandbox, .endless/sandbox/endless/config.json, which has no tmux block. tmux.socket_dir therefore falls back to the default per-user socket directory under the system temp dir, whatever HOME or XDG_CONFIG_HOME say, including under the verify runner, which sets a temp HOME and a private TMUX_TMPDIR. A test or verify suite run from a worktree can reach the user's live Endless tmux servers. Found while writing E-2300's verify suite: a HOME config naming a scratch socket_dir was ignored when run with the worktree as cwd, and the suite had to run its end-to-end layer from a scratch directory instead. Separately, a Python test spawned a real window on the user's endless-tasks server until isolated_env set socket_dir.
