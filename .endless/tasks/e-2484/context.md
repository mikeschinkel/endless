E-2481 moved worktree-sandbox seeding from endless-go sandbox init --mode worktree to endless-go db seed-sandbox. endless sandbox reset runs the seed hook from the main checkout against the worktree's own binary, so main's hook and a worktree's binary can disagree in both directions across the land. E-2481 bridged both: legacySandboxInit in cmd/endless-go/main.go routes the old verb to dbcmd, and .endless/hooks/seed-sandbox.sh falls back to the old verb when the binary has no db subcommand. Both go once every live worktree has been rebuilt from a main that has E-2481. Do not remove before then: an older binary's reset and verify would fail.
