`endless project register` stores the resolved path; the hook sees the raw cwd, misses, and auto-registers. The bound session then reads the duplicate project, which has no tasks, so SessionStart injects 'No tasks yet' for a project that has plenty — the hook logs 'auto-registered project: <name> at <unresolved path>' while the registered row holds the resolved one. Reproduced while writing tests/tasks/e-2001-verify.sh on macOS, where mktemp -d hands back a temp dir under a symlinked parent; the same failure hits any user whose projects live under a symlinked directory. That verify script works around it by resolving the fixture path with pwd -P, so the workaround is test-side only and the product side is unfixed. Fix is to pick one normalization (resolve symlinks) and apply it on both sides, plus decide what to do about project rows already stored unresolved.
