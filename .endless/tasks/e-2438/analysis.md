Two shapes were considered. (1) A language-agnostic check field naming the directory a check runs in (e.g. dir), honoured by every driver, generic sh checks included. (2) A field the language driver declares and consumes, like gotest's existing tests and paths, which the Check type already accepts only on structured drivers (e.g. module on gotest).

Mike, 2026-10-25: dir sounds like a good generic solution however runner-specific fields are handled.

Open point raised with it: what happens when two runners each want a runner-specific field of the same name (e.g. Go and Python both wanting module)? Fields are per check, and each [[check]] names one runner, so the two never meet in one table and each runner reads its own. The cost is meaning, not collision: Go's module would be a directory while Python's is a dotted import name, and Check is one flat struct, so one TOML key would carry two meanings, validated per driver. Ways to settle it when planning: share a key name across runners only when its meaning is the same, or put runner-specific fields in a per-runner subtable (e.g. [check.gotest]) so each runner owns its own namespace.
