Every verify check runs with its working directory at the repo root, and a check has no field to change that. The gotest driver runs go test from the root, which cannot see packages in a nested Go module (a subdirectory with its own go.mod, such as go-dt's dtx). A repo with nested modules must fall back to sh checks (cd dtx && go test ./...), losing per-test CTRF results and selection by test name. go-dt hits this now (E-2375's suite, E-2431's). Other languages have the same shape: a Python subproject with its own pyproject.toml, an npm workspace package.
