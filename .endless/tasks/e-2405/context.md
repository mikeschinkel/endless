`endless task spawn` and `endless task claim` take the project and the repository from the current directory, not from the task. spawn_plan calls _resolve_project(None) and _perform_claim_work, whose project_root defaults to _project_root() of cwd. Neither compares that with the task's own project_id. So spawning a go-cfgstore task (E-2400) from the endless checkout would create a task/2400 worktree in the endless repo, branched from endless's main, and start the session there, tagged with go-cfgstore's project id. The task already knows its project, and the project row knows its directory, so nothing about where to work needs the caller's cwd. A user who manages several projects from one directory hits this on the first cross-project spawn, and recovering means undoing a worktree and a branch in the wrong repository.
