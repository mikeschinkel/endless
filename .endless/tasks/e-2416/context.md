Transcripts live only on the machine that ran the session, so another machine or teammate cannot see the reasoning behind a change. Agreed with Mike while reconciling E-2291: transcripts are large, can hold pasted secrets, and do not belong in a project's git history by default, so capture must be an explicit opt-in. Storage would likely be compressed binary. Some teams will want it to learn why something happened as it did. Pairs with recording session-task links in the ledger by session UUID, which gives a transcript a cross-machine identity to attach to.
