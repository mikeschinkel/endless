Planning E-2403 on 2026-10-19: a valid payload in a new format is the one unreadable-payload case Endless itself must fix, by adapting. The hook decodes into a typed struct (claudePayload in internal/hookcmd/claude.go) that ignores unknown fields and leaves missing ones zero, so a renamed or removed field passes silently. Mike noted typed decoding lets the compiler catch more than a runtime map, and that pinpointing where a format change lands makes a more coherent issue and a faster fix. Agreed approach: keep the typed struct and keep ignoring unknown fields (Claude Code adds fields often, so rejecting them would break on every release); after decoding, check per event that the fields Endless needs are present. A type mismatch already names its field in encoding/json's error.
