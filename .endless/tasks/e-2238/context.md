Since E-2156, `endless project monitor --tmux` runs on its own tmux server, viewed from a terminal window of its own, with a shell pane under the monitor for running `endless` commands. E-2240 replaces that server with the console server (socket `endless-console`) and adds the task-session server (socket `endless-tasks`, session `tasks`), both addressed by `tmux -S <path>`.

Anything that opens a tmux window from that shell inherits the monitor server's $TMUX, so it lands there instead of with the user's task sessions: `endless task claim` (which starts Claude through the spawn-window seam), `task spawn`, and the auto-spawn job when its target is `monitor` (the project monitor fires jobs). Those Claude sessions then sit beside the monitor, whose layout the task sessions do not share, and their liveness reads `unknown` because the monitor server carries no @server_uuid. E-2240 routes spawns to `tasks`; this task covers the rest of what the console's shell does: commands that need no Claude session, the commands it refuses, and `session goto`.

Running `endless` commands from that shell also fails today with "Cannot determine the Endless session for this pane", because the pane has no Claude session.
