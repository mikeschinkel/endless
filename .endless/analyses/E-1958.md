# Analysis

Findings from the E-1941 session (2026-08-12) that surfaced this task. Evidence,
not a plan — the working session owns the design.

## How the gate is implemented today

- `_maybe_auto_sandbox_bind` (`src/endless/worktree_cmd.py`) returns early when
  `config.project_is_self_dev(project_root)` is false, so `task claim` /
  `task spawn` provision a sandbox only for Endless itself.
- `config.py` resolves the sandbox root to `None` for non-self-dev projects
  (`return root if project_is_self_dev(root) else None`).
- `.endless/config.json` carries the flag; only Endless sets it.

So a downstream project's worktree gets no sandbox at all — not merely no
sandbox *DB*.

## The two concerns the flag conflates

1. **Per-worktree scratch/config storage.** A worktree needs somewhere to keep
   the configuration a task requires in order to be *verified*. Essentially no
   real software project has zero configuration files, so this is universal.
2. **DB routing.** Endless-specific, and correctly opt-in: a downstream
   project's worktree tasks must land in the real ledger as real audit data, not
   in a throwaway copy. Sandboxing *that* for downstream users would be wrong.

Today one flag governs both. Separating them is the decision this task exists to
make.

## Why E-1957 is blocked on this: the fault surface is project-blind

E-1957 needs somewhere to persist git conflict evidence when a land fails. The
obvious existing home was the fault subsystem (`internal/faults`), which already
does the right shape of thing — `Fault.Code` + `Fault.Source` discriminate the
producer, and `Fault.Detail` / `Fault.Fields` carry long structured capture to a
JSONL log by design, explicitly "never the DB". No schema change needed.

It was rejected for now because none of it is project-scoped:

- the `errors` table (`internal/schema/schema.sql:882`) has **no `project_id`
  column** — columns are id, code, severity, source, fingerprint, summary,
  occurrences, first_seen_at, last_seen_at, cleared_at, cleared_by
- the JSONL `Detail` struct (`internal/faults/detaillog.go`) has **no project
  field**
- `monitor.ConfigDir()` (`internal/monitor/db.go:61`) returns `dbContextDir`
  when set, else `$XDG_CONFIG_HOME/endless`. A land pins `--db main`, which sets
  `dbContextDir` to the real config dir — so the detail log is **one shared
  location for every project**, `~/.config/endless/log/`

Attributing anything there means smuggling task/project through `Fields` and the
fingerprint: a workaround for a missing column.

If this task gives every project a per-worktree sandbox, per-worktree fault and
evidence storage becomes the natural home and no smuggling is needed. That is
why E-1957 defers its storage decision to this task's outcome rather than
picking a location now.

Two adjacent gaps, noted and deliberately NOT folded in (Mike's call):

- Neither the `errors` table nor the JSONL detail log has any retention sweep.
  `appendDetail` does `MkdirAll` + append with no rotation; only manual
  `endless errors clear` exists. Left for when it is needed.
- Adding `project_id` to `errors` would fix the blindness directly and benefit
  every fault source, independent of sandboxes. Raised, not filed — it may be
  the cheaper answer than universal sandboxes for E-1957's needs specifically,
  and this task should say which it prefers.
