# Two gaps E-1975 does not close

Surfaced 2026-08-21 from ES-1116 (E-1696), where the minimizer ran on a project
whose `report_gate` is false and cut the one thing Mike always wants.

## 1. The guide is not gated; the hook is

`reportChannelOn` (internal/hookcmd/claude.go) resolves the report channel from
`.endless/config.json`'s `report_gate`, and its own comment states the rule:

> a session must never be told to use a channel that will not gate it, nor
> gated without having been told.

The Stop gate and the SessionStart rule both honor that. The STATIC GUIDE TEXT
does not. `docs/guide/index.md` tells every session, unconditionally:

> run `endless task report <id> --draft-file <path>`, and send that command's
> output verbatim as your entire message — an adversarial minimizer deletes
> what your user did not ask for, and a Stop hook enforces both halves.

On endless's own checkout `report_gate` is FALSE, so the final clause is simply
untrue there, and the instruction is exactly the "told to use a channel that
will not gate it" case the comment forbids. Same problem in
`docs/guide/tasks.md` ("Reporting to your user") and
`docs/guide/orchestration.md`.

This is what made a session on a gate-off project run the minimizer at all.

Fix: gate the guide text on the same resolution the hook uses, so a gate-off
project's `endless guide` either omits the step or states it is off here. The
guide is rendered from markdown, so this needs a conditional-section mechanism
or a per-project post-filter — that is the design question, and it likely
generalizes beyond this one section.

PRODUCT: `report_gate` is per project precisely so endless can opt out while
the prompt is tuned. Every OTHER project reads the same guide, so whatever is
built has to key on the reading project's config, not on endless's.

## 2. "A command the user must run survives" is a promotion veto, not a runtime one

E-1975's scoring section already names it:

> **Mechanical invariants** — no model call. Fenced code blocks and tables
> survive byte-for-byte; a command the user must run survives.

But that is scored during the OPTIMIZER's paired replay, to decide whether a
variant gets promoted. It does not constrain the deployed prompt on any given
turn. The observed failure was exactly that: the shipped prompt dropped a
fenced verify command from a draft that contained one, and nothing noticed.
A veto that only runs at promotion time cannot catch it.

Fix: enforce the byte-exact protected-content invariants as a POST-CHECK on
every `task report` call — if the draft carried a fenced block or table and the
minimized output does not, that is a failure, not output. Re-run, or restore
the block. Cheap (no model call, per E-1975's own framing) and it closes the
one failure mode the user is guaranteed to notice.

Sequence after E-1975 if the runtime and the optimizer should share one
implementation of the check; do it independently if E-1975 stays parked.

## 3. Doc rationale that dies with deletion-only (fold into E-1975 if easier)

`docs/guide/tasks.md` justifies "Do not pre-summarize" with:

> The minimizer can only cut what it is given.

That premise is false once ED-1557 lands. The INSTRUCTION should probably
survive — the other stated reason, that pre-summarizing destroys the raw draft
the eval corpus learns from, holds regardless — but the reasoning has to be
rewritten, not just left standing.

Evidence it is already false in practice: on the observed turn the deployed
deletion-only prompt produced prose present in neither the draft nor the
conversation, synthesized from the user prompt plus the draft. The shipped
invariant is not holding today, which is worth knowing independently of
E-1975 — `report_prompts.py` ("you are deleting, not rewriting") does not
bind the model.
