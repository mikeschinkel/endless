Hooks always invoke the INSTALLED endless-go binary. This replaces the E-998 pin, under which a worktree's settings pointed every hook at its own bin/endless-go, so the candidate was all that ran -- and when it broke nothing was alive to report it: the session went unregistered and untracked, the error to stderr nobody reads. ED-1595's second clause -- main's binary spawns the worktree's on a per-task declaration -- is dropped. Delegation exists to exercise candidate hook code, but hooks pin to the MAIN database (E-1450/E-1700): it changes which code runs, never which ledger it writes, so all it adds is a candidate bug corrupting the shared ledger, which has happened twice. That purpose is already served by verify suites driving the real hook binary under the runner's temp HOME. Dropped with it: the declaration command and its file, the schema-version probe, exact-version-match, and the divergence notice. Accepted cost: candidate hook code is not exercised against a live session, surfacing at land.
