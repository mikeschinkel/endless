Every correcting entry written by 'endless correct' carries a reason, required at the command line, and keeps a copy of the corrected row's values from before the change. The reason is for the person reading the ledger later: the change entry says what moved, the correction entry says why. This holds for every operation, including a soft removal that only sets removed = 1, so that a removal done as a correction is never an unexplained one. Mike settled this while answering EQ-252 on E-2486 and asked that it be persistent rather than re-decided per case.
