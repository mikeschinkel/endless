A connect requires exact agreement between the binary's schema version and the database's, and acts BY DIRECTION; replaces apply-on-connect in monitor.DB(). DB BEHIND: an INSTALLED binary auto-applies forward, unconditional in non-self_dev which has one binary; a CANDIDATE binary refuses, since it may never migrate the real ledger -- the 2026-08-10 failure exactly. DB AHEAD: HALT, for any binary; it must be upgraded. No compatibility window and none to derive: an older binary writing a newer database is unsafe even when every migration was additive, because the new columns exist because new code populates them, so its rows are permanently incomplete and no upgrade recovers what was never recorded. Rollback is restoring a pre-upgrade backup (E-1942), not tolerating a mismatch. Accepted consequence: a self_dev branch carrying an unlanded migration has its candidate hook degraded for the whole pre-land window, reducing what E-998 exercises there -- the price of never letting unlanded code mutate the schema.
