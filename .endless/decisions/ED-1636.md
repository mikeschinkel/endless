A post-land item is a plan item whose work needs the landed, migrated, locally installed result. It stays in the parent's plan rather than becoming a follow-up task, because a follow-up costs a filed task and user attention (ED-1550) and a post-land item needs none of a task's lifecycle: no worktree, verify or land. The dividing line: a post-land item produces no code; work that would produce code is a follow-up task, since code needs its own verify and land. A task landed with deferred items goes to a new status, landed, rather than assumed; it moves to assumed when reconcile records the last deferred verdict, may go to revisit, declined or obsolete, and never directly to confirmed. A failed post-land verdict keeps the task landed until a later reconcile records the pass. Rejected: splitting every post-land item into a follow-up task; landing to assumed with the item visibly open.
