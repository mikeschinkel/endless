Once `sessions.active_task_id` is set it is never cleared — it may be superseded by a new claim, but never returned to NULL; ownership history that outlives supersession belongs in an append-only `session_tasks`, not a single mutable pointer. The binding is the only path from a task back to the session that did its work (`ResolveResumeTarget` resolves a task ref through that column and nothing else), so clearing it destroys the record and strands a live transcript. This overturns two current positions: the `task reopen` path deliberately NULLs the binding "so retrospective queries see a clean handoff", which has the inverse effect; and E-1967 had encoded NULL-on-release as a fixed premise to design around.
