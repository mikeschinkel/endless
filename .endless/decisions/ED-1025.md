When task confirm --cascade --outcome 'x' is invoked, the outcome is recorded on the root task only. Descendants are confirmed via existing cascade logic with no outcome set. Rationale: each task's outcome is unique to that task; copying the same outcome string across descendants would be misleading data. Matches existing cascade UX where only the root gets explicit attention (status echo, etc.). Same rule applies to assume --cascade and any future cascade-bearing terminal-status command.
