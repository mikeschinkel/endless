The objective is not "cut what was already said". It is: cut what the user will have to review ANYWAY -- what session status already shows, and what is written into a task, a decision or another durable artifact. Saying it in chat too means they read it twice. An earlier chat reply is not such an artifact: chat is ephemeral and the user is reading THIS message, so restating a verify command from two turns ago is not duplication and must not be cut. Written as "already sent", with prior replies fed in as context, it deleted the table, the code block and the verify command together in 2 of 8 live runs, leaving one sentence. Prior chat replies are therefore not a deduplication source. Nothing here competes with the invariants; the objective was simply written wrong.
