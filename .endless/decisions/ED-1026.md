The 'outcome required when status=declined' rule lives in a single helper _require_outcome_for_declined(status, outcome) in task_cmd.py, called by decline_item, update_plan, and replace_task. CLI commands surface the resulting ClickException but don't duplicate the check. Rationale: centralization ensures all entry points behave identically, even ones added later that bypass current CLI verbs (e.g., future Web UI calls into update_plan). Defense-in-depth in the Go executor was rejected because it kicks in too late (after CLI accepted) and complicates rebuild-db replay.
