Plan-attach by an agent no longer auto-promotes to 'ready'. Lifecycle becomes: unplanned -> (agent attaches plan) unapproved -> (human runs endless task approve) ready -> underway -> unverified -> confirmed. 'ready' now provably means human-approved, so background loops may pick up only 'ready' work. Enforcement gates: (1) remove the auto-promote; (2) forbid kind=background sessions from approve and from picking up non-ready work (session kind is known). A tmux-driven agent running approve stays a convention (the system can't distinguish human from agent in a pane) — accepted. Related calls in the same status-model rework: 'blocked' is dropped as a stored status (blocking is derived from the blocked_by relation), and the vocabulary is renamed (needs_plan->unplanned, in_progress->underway, verify->unverified) with a new 'unapproved' state — see E-1252/E-1532.
