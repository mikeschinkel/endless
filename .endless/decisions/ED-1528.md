Whether endless is 'in a sandbox' is a property of exactly one thing: the resolved endless.db config dir lying inside the sandboxes root. Everything sandbox-conditional — DB routing, ledger routing (ED-1525), any future conditional — keys on that predicate. A sandbox directory's existence is never a signal: sandboxes are a general product concept (any project may have one, holding project-specific files via hook scripts), so existence says nothing about DB context. The only user-facing chooser of that config dir is --db, and it is a self-dev-only flag: a non-self_dev project has exactly one DB, so BOTH --db values are rejected loudly there; within a self_dev project, --db main is valid anywhere (escaping the sandbox is always meaningful) while --db sandbox additionally requires cwd inside a worktree; and inside a self-dev worktree an explicit --db is required for any DB open, reads included — no default is ever accepted (the E-1429 gate).
