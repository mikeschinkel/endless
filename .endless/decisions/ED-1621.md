Defines the term "primed session". The process was agreed in E-1994; its name never was until now. A primed session is a task's implementation session that Endless starts before anyone asks for it. It starts either from the prime job, when a project opts in with prime.enabled, or from endless task prime <id>. It reads the task in, drafts a plan when there is none, asks the questions it cannot answer, and ends its read-in with endless session primed. That sets the session state primed, and the session holds there until its user resumes it. The resumed session's task claim is what starts the work: until then the task stays pre-work (unplanned, submitted or ready) while the session owns it through sessions.task_id. Primed names the session's state, not the task's status: a task is never primed.
