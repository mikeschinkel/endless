verify.toml is a specification (public artifact, working name trust-but-verify.org), not an Endless-internal format; tbv (Trust But Verify) is the Go reference implementation (in endless-go now, extracted later), others may implement in any language. Three levels, modeled on IANA/HTTP where OAuth's SHOULD/MAY fragmented: (1) the GRAMMAR, HOW-agnostic; (2) a REGISTERED runner-type registry whose behavioral contracts (selection, result format, launcher behavior) keep the same file behaving identically across implementations; (3) CUSTOM types. The verifier is always a Go binary in our stack: 'no Endless present' means no endless executable, never no Go executable. Drivers EXECUTE runs in Go (never emit a command for an outer shell); how we run a given runner is implementation code, not spec. Full design in the E-1789 outcome.
