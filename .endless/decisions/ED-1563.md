When a bug writes bad rows, the fix has two halves and both ship: the code stops producing them, and a per-ticket change file (ED-1472) repairs the ones already there. Tolerance at the read boundary is the fallback for rows written by hand or restored from an old backup — it is not a substitute for the repair, and it must not become the reason the repair is skipped unless the user explicitly approves skipping it. Rationale: leaving damage in place pushes the cost onto every later reader and onto CLAUDE.md prose explaining the workaround, which every session then pays for. Repair is bounded work: E-2002's was ~150 lines, with FK columns discovered via PRAGMA foreign_key_list so the sweep cannot go stale. A merge that must repoint references is the normal shape of it, not grounds to defer — history hanging off a duplicate row is moved to the survivor, never cascaded away.
