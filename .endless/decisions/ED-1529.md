Consolidates the task status workflow into one source of truth, superseding ED-1522, ED-1513, ED-1498, and ED-1499. Canonical lifecycle: unplanned → submitted → (Mike approves) → ready → underway → unverified → confirmed|assumed, plus revisit and terminals completed|obsolete|declined. `submitted` = spec-complete, agent-set, awaiting approval — reachable by attaching a plan (auto-move on --text) OR `task submit`; plan-vs-no-plan is carried by tasks.text, not status. Gates: attaching a plan now moves unplanned→submitted (was →ready); `task approve` (human) promotes submitted→ready and is refused for background sessions; a background session may claim only `ready` work, so `ready` provably means approved. Blocking is the blocked_by relation, not a status. Formalizing the status set (values-table/FK, any `blocked` removal) is E-1532's separate concern; this governs the current free-TEXT status column. The mermaid in README/CLAUDE/guide renders from one file (docs/status-lifecycle.mmd).
