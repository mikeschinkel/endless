Resolving which Endless session and task a tmux pane belongs to has ONE canonical implementation: monitor.GetActiveTaskForPane in internal/monitor/tmux_lookup.go. It tries the pane itself, then all panes in the same window via listPanesInSameWindow, and selects the session with the newest last_activity where state != 'ended' (NOT state in working/idle, which wrongly excludes bound and other live states) and active_task_id is not null. Established by E-1530 (ghost-row fix for reused pane ids after a tmux server restart). The status line and all future window-aware readers, including session next (E-1465), MUST call this resolver rather than re-deriving pane-to-session logic. The session-next prototype replicates it in shell only as throwaway scaffolding; the Go command must call GetActiveTaskForPane directly.
