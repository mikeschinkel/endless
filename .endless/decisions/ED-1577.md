Endless is developed against its own ledger, so real task ids leak into help text, guide pages and error messages — where a user running Endless on their own project cannot resolve them. But docs still need ids that look like ids, placeholder forms make examples materially harder to read, and an id's position does not tell you whether it is an example or a citation (option help carries examples inline, and Click rewraps them). So: reserve ids 1-199 as the documentation-example band. Every hypothetical id is written there; anything above reads as a citation and is refused. The band is an authoring convention, not a fact about how far Endless's own ledger has counted, so it holds for any project. A range check has nothing to append to and so nothing to erode, unlike an allowlist of known-example ids. Enforced by tests/test_no_self_dev_ids.py, whose failure message states the band and the three fixes: delete the citation, restate the fact it stood in for, or renumber the example.
