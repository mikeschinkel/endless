canAmend's precondition 2 asks "is HEAD reachable from another ref" (`git for-each-ref --contains HEAD`) — a SHA-level question that any history rewrite invalidates, after which the guard permits an amend that diverges main from every task branch's base and conflicts on the ledger segment at land. Add a second, content-level reason to refuse: before amending a ledger tip, compare the `.endless/db-ledger` tree hash at HEAD against every `refs/heads/task/*` tip; if any branch holds a byte-identical ledger tree, append instead. A tree hash is content-addressed, so it survives any rewrite — the durable fork-point identity the SHA test lacks. Precondition 2 is retained, not replaced: the content test scans only task branches, so it is blind to a ledger commit already pushed or tagged. The two are OR'd. Measured at 16ms across 145 branches; the patch-id alternative costs 71s per event and is struck. Amend is preserved and self-releases, costing one extra commit per rewrite.
