Eligibility is computed at spawn-decision time from the task's complexity and risk ratings, not stored as a flag, so it always reflects the current ratings and thresholds. Agents propose both ratings at submit; the user ratifies them at approve, reusing the existing approval gate rather than adding a second one — the intent being that an agent cannot relax its own auto-spawn gate. Note when reviewing: that last property is weaker than it reads. `approve` mechanically refuses only a kind=background session; for an agent in a normal tmux pane the system cannot distinguish it from the user, so the gate is by instruction, not enforcement. Two orthogonal axes rather than one scalar, per ED-1539.
