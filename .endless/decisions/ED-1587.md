Task worktree branches are named task/<id> — bare id, no title slug, no configurable pattern. Supersedes ED-1167, which accepted slug drift rather than removing it; its no-rename rationale (remote/PR/CI fallout) does not apply to local-only task branches. Why: (1) composability — a branch name can today only be looked up, never constructed, which is why task_landings.branch exists; task/<id> makes it a pure function of the id; (2) that column and its NULL case go away, taking E-1719's record-only carve-out and the git fallback E-2087 added to name a branch no landing row recorded; (3) titles are edited routinely and slugs frozen at creation, so a slug branch names what the task used to be called. Rejected: a configurable pattern, which reintroduces the lookup this removes and strands existing branches when changed; revisit if users ask. Not a rationale: finding a task's commits, which git log --grep already does. Migration of existing slug branches is left to the implementing task.
