The verify runner substitutes HOME and XDG_CONFIG_HOME with a per-run temp dir. On macOS that dir sits beneath a symlinked prefix, so every suite ran under a HOME reached through a symlink — which a real home directory almost never is — and any code comparing a resolved path against a joined os.UserHomeDir failed inside a suite that had nothing to do with the change being verified. E-2023 plan argued the neighbouring case as "a break is a finding, not a regression"; that holds for a suite secretly depending on the real database, where the dependency was always a contract violation, and does not transfer here. A difference the isolation itself introduces is the isolation bug: it is not a property of the system under test, it makes verdicts platform-dependent, and it misattributes failures to the wrong task — the one thing a verification front door must never do. Binds the Tier 1+ substrate ladder.
