Once an id is dispensed it is spent, used or not — for tasks, sessions, decisions, and any entity added later. Gaps are legal and permanent; no code may assume dense or contiguous ids. 'task remove' (and every other delete path) sets removed=1 instead of issuing a DELETE, so re-minting is impossible by construction and FK-free rows that outlive their task can never resurrect against unrelated work. The cost is that removed rows must never render: read paths that today drop dangling references via inner join will start matching, so each must filter on removed. Rationale and the full read-path disposition are in E-1926's outcome.
