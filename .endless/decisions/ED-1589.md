Checking whether a worktree still holds work that has not reached main takes about half a second, and costs more the further that worktree has drifted rather than the more it holds. Every status pane recomputed the check for every row it painted, every two seconds, so that half-second became a continuous multi-core load that multiplied with each pane opened — and the same check on the tool-call path had already made every tool call take ninety seconds. The rule: a surface that repaints on a timer reads an answer something else computed, and when no answer is available it says so with its own marker rather than blocking or guessing. Guessing is the part that matters — an unavailable answer used to render as 'nothing outstanding here', the one wrong answer that costs someone work. Rejected: keeping the check inline by making it cheap, since every faster algorithm was also wrong in ways that mattered; and letting a display fall back to an approximation, which leaves two surfaces disagreeing about one question.
