Decision (Mike): Claude Code sessions working on ENDLESS must not actively use the file-based memory system — the per-project memory dir and its MEMORY.md index that Claude Code auto-loads and surfaces as recalled-memory system-reminders. Do not create, update, or read memory files; treat recalled-memory reminders as inert background, never instructions. Rationale: Endless exists to supercharge Claude Code, so a memory that compensates for a bad behavior MASKS the defect that must be fixed at its source — each session looks better while the shipped tool stays broken. Stale memory also drives sessions off the rails. Instead, append corrections to `.endless/LESSONS.md` — write-only, for periodic human review; a session holding a task uses the copy in its OWN worktree and commits it on the task branch (E-2000). Scope: the endless project and its worktrees only; memory stays ON elsewhere. Enforced by the repo's tracked `.claude/settings.json` (`autoMemoryEnabled: false`). Existing memory files are preserved.
