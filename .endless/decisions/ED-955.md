Decision context: planning E-949 (refactor Endless config loading onto go-cfgstore). Question: when both ~/.config/endless/config.json and <proj>/.endless/config.json define a 'checks' map, should the project map fully replace the global map (whole-map), or override only the keys it explicitly sets (per-key)? Decision: PER-KEY. Rationale: Mike confirmed each key can potentially need its own merge semantics, so per-key gives the most flexibility. Whole-map would defeat the use case where a project sets just one check and silently loses inherited defaults for all others. Implication: Merge() in internal/config/merge.go iterates the global map keys and only overrides those explicitly present in the project map.
