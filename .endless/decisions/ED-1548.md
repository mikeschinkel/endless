A single universal sequence shared by tasks, sessions and decisions (so a bare 12345 would be unambiguous and E-12345 would preclude ES-12345) was considered and rejected. Rejected because pluggable ID providers cannot honor it — JIRA namespaces per project, GitHub shares one sequence between issues and PRs only — so the guarantee would evaporate exactly where E-800/E-1831 lead; because sessions are the highest-volume entity and would inflate the short-id space that both task and session ids are typed from by hand; and because ids are already embedded in immutable artifacts (commit subjects, branch names, worktree and sandbox paths, plan and ledger prose), so renumbering would make history lie. The E-/ES-/ED- prefix stays part of the identity. The real problem underneath — an id in a plan must mean the same thing to every developer — is cross-developer, not cross-entity, and belongs to E-1831.
