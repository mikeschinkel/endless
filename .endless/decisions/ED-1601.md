The installed binary talks to the main database; a worktree-built binary talks only to its own sandbox. monitor.DB() refuses a worktree build aimed at the main database before opening it, at every schema version. --db stays mandatory inside a self-dev worktree so the choice is always explicit, and the Python CLI routes by it: --db sandbox runs the worktree's endless-go, --db main the installed one. Consequence: only the installed binary ever migrates, seeds or runs the enum integrity gates against main, so the schema-passive ownership branch is gone, and worktree land records its landing with the installed binary after rebuilding it rather than with the worktree's. Narrows ED-1570's 'a candidate refuses when the database is behind' to 'a candidate never opens main'. Main is $HOME-relative, so a verify runner's temp HOME is main for its suite.
