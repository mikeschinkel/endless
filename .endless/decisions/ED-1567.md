Replaces apply-on-connect in monitor.DB(). A connect compares the DB's migration version against the binary's and acts BY DIRECTION. DB BEHIND the binary: the binary needs DDL that is absent, so an INSTALLED binary auto-applies forward -- unconditional in non-self_dev, which has one binary -- while a CANDIDATE binary refuses, because it may never migrate the real ledger, which is the 2026-08-10 failure exactly. DB AHEAD of the binary: HALT, for any binary. Per ED-1570 a binary works with exactly one schema version, so there is no compatibility window to evaluate; the binary must be upgraded, and rollback is served by restoring a pre-upgrade backup (E-1942). Accepted consequence: a self_dev branch carrying an unlanded migration has its candidate hook degraded for the whole pre-land window, which reduces what E-998 exercises on precisely those branches. That is the price of never letting unlanded code mutate the production schema, and it is worth paying.
