Replaces the roll-our-own approach. Chosen over golang-migrate (SQL-only; the five existing .go change files that query mid-migration have nowhere to go) and Atlas (declarative, external CLI + HCL dialect; heavier than needed). goose supports SQLite, supports Go migrations as well as SQL, embeds via the go:embed directive plus SetBaseFS so migrations ship inside the binary, and works as a library rather than only a CLI. This knowingly re-adopts versioned migration, which Endless removed early on in favor of schema.sql-as-source-of-truth; that trade was right while the schema changed rapidly and is no longer right now that it doesn't, with the cost having moved to outages when two binaries disagree about the schema.
