Three rules govern task content (extends E-1058's description policy and grounds E-1064's audit). (1) Analysis is pre-plan/pre-implementation design content only; once a task ships the analysis is historical record, so auditing it for currency is a category error. (2) NO durable content — description, analysis, text/plan, outcome, or a decision body — may include time-frozen specifics: byte counts, file sizes, line numbers, path:NNN citations, match counts, or sha hashes of moving artifacts. They have near-zero historical value and create false-precision drift, and a plan citing them is stale the moment anything else lands, which forces the implementing session to decide whether to override it and pushes that judgment onto the user. Cite durable identifiers instead — function, handler, command or symbol names — or better, state the SEARCH that finds the sites rather than the sites themselves. (3) When a task's plan fully documents the chosen design, analysis MUST NOT be NULLed; it is a historical record.
