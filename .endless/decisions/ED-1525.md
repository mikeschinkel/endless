The ledger is the active DB's WAL and lives next to it. Main DB -> real project ledger, auto-committed on main at write time (unchanged; E-1206/ED-901). Sandbox DB -> db-ledger/ inside the sandbox dir; never touches git; erased atomically by sandbox destroy. One in-code resolver returns the ledger target (root + commit-or-not) alongside DB-context resolution; all four CommitLedgerSegment callsites and both ProjectToTempDB callsites consume it — no flag, no env var, no config file. Reads are symmetric: validate-db/rebuild-db replay the active context's ledger. Rejected: worktree-hosted ledger incl. gitignored subdir (guarded-against not structurally-safe; splits DB/WAL lifecycle), DB-only emits (breaks events-authoritative), projects.path repoint (lies about project location; commit hard-fails), git-init sandboxes (commits nobody reads).
