Going forward, terminal-status transitions (decline, confirm, assume, replace) emit a single task.fields_updated event with both status and outcome (if provided) in one payload, rather than the prior pattern of task.status_changed for status changes. Consequence: complete_item and assume_item, which previously emitted task.status_changed, switch to task.fields_updated. Old events still replay correctly via the existing task.status_changed handler in projector.go and executor.go — those remain in place. Rationale: atomic write of status+outcome avoids replay-ordering questions, matches update_plan's existing pattern, and consolidates the event shape vocabulary.
