An agent must name the database on every command that reaches one (--db main|sandbox), whatever its cwd and however many are reachable. A human names it only where the choice is ambiguous — inside a self-dev worktree — so the cwd-based gate (config.gated_worktree_root, E-1429) is unchanged for humans. The risk is asymmetric: a human sees each result, while an agent runs commands in sequence with an inherited environment it did not set and reports success from an exit code, so implicit routing makes its mistakes silent and plausible. On 2026-08-20 an agent filed a task without --db from the main checkout; the worktree gate correctly stood down while an injected XDG_CONFIG_HOME still selected the sandbox, and only a missing schema column stopped it reporting a task ID that existed nowhere the user could reach. E-1964 deletes that injection but not the general case. Enforce at config.require_db_context / go_db_context_args, keying caller type on CLAUDECODE / internal/agentenv.
