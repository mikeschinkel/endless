Concurrency is the wrong thing to limit: the scarce resource is review capacity, so a concurrency cap still buries the user, just slower, while a review-queue limit speeds up exactly as fast as the user reviews. But it must count auto-spawned unverified, not total. Measurement forced this — 57 unverified in endless, 75 machine-wide, 71 of them aged 30-90 days. That is sediment, not a queue: an 80-day-old unverified task awaits a decision about whether it is still real, not attention. A cap of 3 against a floor of 57 never clears and the feature ships dead. Counting only auto-spawned output is self-limiting at any backlog size; switching to a total count later is a WHERE clause, and draining the sediment proceeds orthogonally as E-1977. Scope is per project; a machine-wide ceiling is deferred as untestable today. A session paused on a permission prompt counts, since a prompt is a claim on attention and the cap measures claims on attention — safe only because E-1976 renders that loudly.
